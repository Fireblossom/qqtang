# 控件声明透明度、渐变边界与回调

2026-11-04。核对探险侧栏时确认头像坐标正确，同时发现宿主忽略了 `alphafactor/alphaspeed/minalphafactor` 声明。本轮接入这三个属性、原版渐变状态机和绘制透明度量化。

## 坐标与属性

原版 `uiGame.py` 的玩家头像位置为(2,80)、(2,160)，遮罩为(0,120)等；两张头像画布均55×55、帧偏移(0,0)。旧实局截图的头像顶部共4336个不透明像素与资源在上述位置逐点完全相同，没有几何误裁切，不移动头像。

PVE头像/遮罩均声明 `alphafactor=0.8`；房间能力上限条有0.5，聊天泡背景有0.6及最小值0.6。实际属性加载 `gameUI.dll 0x1002B42F` 把三种声明分别写到控件+158/+150/+160。属性加载段按原始指令/伪C核对；本轮没有执行完整Python2属性解释器。

真实完整控件构造 `0x100267B8→0x1002650D` 初始化速度1.0、当前1.0、最小0.0、有效1.0、方向0。宿主现在读取声明，缺省/None沿用默认，显式0不会被当成缺省1。

## 状态机与绘制

实际执行 `0x10027580`、`0x10027892`、`0x1002A017` 和 `0x100297F3`：

- 通道41设置/读取渐变速度，42设置/读取当前透明度；904设置最小透明度；901只接受值1/2，其他值保持旧方向。基础getter对901/904返回-1。
- 每次控件更新只走一步，速度不是毫秒单位。方向1增加，严格大于1才钳制并清方向；方向2减少，严格小于最小值才钳制、清方向并调用 `OnDisappear`。恰好等于边界时仍保留方向。
- 透明度字段为double，但D3D未保留FPU精度后的运算使用PC24；运算结果按float32舍入后存回double。0.8以速度0.1向0.6淡出，实际第1帧0.699999988079071，第2帧已越界并回调。
- 根控件直接使用当前值，子控件有效透明度按父有效值相乘并舍入；图片颜色Alpha为有效值×255的截断字节。0.8对应实际ARGB `0xCCFFFFFF`，0.5为 `0x7FFFFFFF`，量化为0时不发图片绘制调用。

宿主已实现以上规则、父子调制和回调，保留遮罩/生命条各自按时间更新的逻辑。主循环仍为宿主60Hz；此函数对照不等同于源Win32完整帧率/调度或D3D最终像素混合验证。
