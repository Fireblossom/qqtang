## 原版数据与使用条件

`PropSet/IDxxxxx` 的 `Tier` 是共享冷却组；`PickedUpState.InitialInterval` 是从场景时间零点开始的等待，`GameMode` 由 `0x005FC892` 检查：0都能用、1非规则12、2仅规则12。`PropFireIntervalTable` 给出各 Tier 的间隔。既有 `LoadAdventureProps` 已读 Tier 和 InitialInterval，本轮补读 GameMode。

| 道具 | Tier / 间隔 | 开局等待 | 模式 |
| --- | --- | --- | --- |
| 20020 万能药剂 | 3 / 15000ms | 20000ms | 两种 |
| 20008/20009 陷阱 | 3 / 15000ms | 20000ms | 两种 |
| 20058～20064 礼花 | 102 / 1000ms | 0 | 两种 |
| 20050 医疗包 | 1 / 5000ms | 0 | 仅规则12 |

`0x005F7CC5` 检查模式、场景时间达到 InitialInterval，以及该施法者的同 Tier 上次使用时间已过间隔。`0x005F7E49(Tier,PlayerID)` 查询上次时间；`0x005F7E20(Tier)` 查询间隔。人类收到确认后 `0x005F81F4` 用当前场景时间写入组记录。NPC 的独立同组冷却已有实现，本轮不改 NPC 技能。

sidecar 现向宿主返回每项带入道具的 `cooldown`（initial、interval、last_use、allowed）。只在本机玩家的0x1175确认到达后记组时间和扣数量；请求阶段不扣数、不开始冷却。其他玩家的使用不改变本机冷却。开局/同组冷却期间不发0x1174，Ctrl会跳过尚不可用的带入道具，继续找后面的可用槽。

已加载的原版 PropSet 中没有该道具时，按原版缺失对象分支禁用；这也覆盖配置已移除但库存/目录仍留着的旧道具。没有读取到原版表的纯单元测试仍可使用无元数据的旧测试桩，不把未知表值编成虚构间隔。

## 遮罩公式

状态栏写入函数 `0x005DAC82(slot,item,count,Tier)` 是普通代码。只对20001～22999处理冷却，查本机准备道具对象；对象不存在或模式不符，脚本回调速度0、当前角0，显示完整遮罩。

道具可用时：

```text
初始控件由 InitItemTime 设置当前/目标角360，已经清空
now < initial:
  speed = 360000 / initial              // 度/秒
  current = now / initial * 360
last_use != 0 且 interval != 0:
  elapsed = uint32(now-last_use)
  current = min(360, elapsed / interval * 360)
  speed = 360000 / (interval+400)
```

`+400ms` 只用于遮罩动画速度，**不延长可使用时间**。没有上次记录或间隔为0时，原函数不覆盖前面的初始状态。宿主根据场景时间刷新角度；库存数量不变时也更新。空格和拾取道具槽保持360，不留红圈。底层DYMASK仍按 `ui-dymask-re.md` 从十二点顺时针擦除。

Unicorn隔离调用完整 `0x005DAC82`，替换图标/脚本桥、道具查询和可控的组记录，捕获 `ui_SetItemTimeSpeed/Cur`：

| 输入 | 当前角 / 速度 |
| --- | --- |
| initial10000、now3000、无上次使用 | 108° / 36°每秒 |
| last10000、interval5000、now12000 | 144° / 66.6666666667°每秒 |
| 同上，now15000 | 360° / 66.6666666667°每秒 |
| 对象缺失或模式不符 | 0° / 0 |
| 初始已结束、没有上次记录 | 不发遮罩回调 |

原始探针和结果：`/private/tmp/qqt-prepared-re/probe-mask.py`、`mask-results.jsonl`。受保护的混合槽位调用方仍待追踪，实际CALL还包括 `0x005BA26F`、`0x00880BC8`；跨入玩家初始化的通用探针缺少主程序全局工厂，未将其结果用于推断排法。
