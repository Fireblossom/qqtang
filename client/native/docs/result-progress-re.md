本机标题旁的等级脚本收到“资料积分+Score总和”。各列表行则按原生等级序号i传 `等级阈值[i]-1`，不能直接传上述积分。原生阈值判断为包含上界，UI Level脚本判断为严格小于；这使恰好整级积分时两条路径存在原版边界差异，本轮保留它。

## 经验条的真实纹理调用

`0x006137BB` 使用图片原始帧，而不是普通CImage包装；忽略DIMG帧偏移。两层顺序为：

1. misc462，裁到目标百分比×3.83px，实际帧385×11。
2. misc317，裁到当前百分比×3.83px，实际帧383×10。

图形接口+118收到四个 `(x,y,z,u,v)` 顶点，坐标以屏幕中心为原点、Y向上。GFX的 `0x10006D5C` 按半屏宽/高转换包围框；800×600下，普通base=30得到屏幕左上(168,205)，探险布局base=130对应(268,205)。不能将原始负X当成屏幕坐标。DIMG462的帧偏移(1,1)在这条原始纹理路径上不参与位置计算。

宽度保留原生float32乘法结果；pygame最终以整像素裁切，未宣称分数像素边缘与Direct3D逐像素一致。完整的顶点/UV、纹理编号、颜色FFFFFFFF和flags=0均记录在fixture中。

经验条在控制器phase3出现，颜色始终FFFFFFFF，不随文字alpha渐入。每次phase3更新：

```text
仅当前值 < 目标值时：
  当前值 = float32(当前值 + dt * 目标值 * 0.001)
  超过目标则夹到目标
```

例如20→80，20ms一次，第一帧21.600000381；500ms约59.999977；最终夹到80。跨级95→5时原版不倒退，也不先补到100再归零；前层保持95，底层目标为5。本轮按原版保留这个行为。
