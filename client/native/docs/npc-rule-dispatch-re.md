# 规则8 NPC不派发普通放泡命令

2026-11-04，v848。移除此前没有调用链依据的500ms自动放泡。500ms属于安全移动思考门控，不能转用作放泡频率。

## 注册表与调用链

`0x005F47A9` 创建规则；规则8构造器 `0x00609C0F` 只调用基础构造器并设置虚表/规则号，不隐式安装普通命令。普通规则注册 `0x005F4D57`，规则8注册 `0x00609DF9`；两者各20个命令，但集合不同。

普通放泡命令执行入口 `0x00610BA0` 只在普通规则注册，其NPC分支调用Actor虚表+6C（`0x005B050C`）。规则8安装 `0x00616813` 推箱命令，没有安装 `0x00610BA0`，也没有先调用普通规则注册器。推箱命令检查Space、前方22px和箱子，不调用NPC放泡虚函数。

`0x005C87B0` 在本机玩家等于仲裁方时遍历NPC，逐个运行 `0x005F43B1` 命令派发，再调用 `0x005F3D0A` NPC移动。派发器先跑同格/异格组件，再跑通用组件；每个组件后用真实 `0x005A287F` 重新查实体。移动命令 `0x006112AF` 经虚表+70调用 `0x005B0C1D`，其中规则8第12次更新触发，与放泡独立。

NPC虚表 `0x007A1D2C` 的+30确为基础角色帧更新 `0x005ABE96`。+60的 `0x005B03D4` 确实会依次调用+6C与+70，但在这条默认更新链中没有调用它。不能因为该函数或AIType2的放泡实现 `0x005DF009` 存在，就把它接入规则8。

## 实际执行对照

`tools/probe_rule_commands.py` 执行真实规则/命令构造器、注册函数与分类getter，只有注册存储受控，得到 `rule_commands_v848.jsonl` 两条完整命令表。

`tools/probe_rule_dispatch.py` 将这些真实对象放入原生场景命令向量，执行整个 `0x005F43B1` 与 `0x005ABE96`；原生拾取管理器 `0x005D3462` 初始化容器，角色移动控制器使用原版默认状态。观测AI入口代替执行规划器，空地图查询、NPC分类、移动setter及UI/脚本为控制依赖。

角色25/26/27各跑40帧及200帧，dt20ms，普通规则与规则8共12条序列，合计1440次派发及1440次角色帧更新：

| 规则 | 40帧放泡入口 / 移动入口 | 200帧放泡入口 / 移动入口 |
| --- | ---: | ---: |
| 普通1 | 40 / 5 | 200 / 28 |
| 箱子8 | 0 / 3 | 0 / 16 |

三个角色结果相同。普通放泡调用返回地址为 `0x00610C2C`，移动为 `0x006113A3`；没有角色帧更新阶段的AI调用，亦没有组合入口+60调用。200帧跨过默认角色状态的3000ms期限。

范围是空地图、无输入、默认活动状态、位置保持同格的仲裁NPC。跨格组件的完整动态执行因属性保护容器依赖未纳入本序列；注册表及其普通反编译代码已检查。没有运行整个Windows场景、D3D、主动道具、变身或其他特殊状态，不把本结论推广成“任何来源都不可能给NPC生成泡”。
