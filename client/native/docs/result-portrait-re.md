## 动作、部件与位置

实际执行 `0x005DCF44/0x005DD02A/0x005DD1C3/0x005DD365/0x005DD38D`：

- 角色编号小于32时，负切动作8=lose；胜与平切动作10=win，朝向270度。32号及以上不切换这两个动作，保持stand。
- 角色部件画布普通左上为 `(base+28,84)`；base普通30、探险130。41号初始化采用另一高度，画布y=74。
- 原始角色阴影是misc131_stand：普通位置 `(base+58,143)`，41号y=133，再保留图片自己的帧偏移。它随完整角色绘制。
- 结果角色工厂仅按角色/队伍创建默认模型，未读取房间穿戴列表来替换部件；本轮结果调用使用该默认模型。

部件选择还包含一个容易误读的约定：INI的win/lose值是启用该动作的部件，文件编号仍沿用stand中的基础编号。角色1的win配置cloth=10104，但原版实际构造的是 **cloth10101_win.img**；负是cloth10101_lose.img。通过原版 `0x00453A60 → 0x004269F0 → 0x0061FD25` 核实。角色1/2/18的这些动作只启用cloth，图片本身含完整身体，不叠站立的头发、手脚或服装。

AvatarCache现在对win/lose按上述原生选择读取，并保留每个部件的独立帧输入。缺少动作资源时不擅自回退stand；例如31号允许切动作，但原包没有其win/lose图片。该失败图片的内部时钟不算已复刻的可见动画行为。

## 200ms部件时钟

原始图片数据构造 `0x00487360` 默认循环；部件加载 `0x00425F10` 通过 `0x00427340` 将周期设为200ms。执行原版角色更新 `0x005DD161 → 0x00425020 → 0x004262F0` 得到：

```text
remainder += dt
frame += remainder / 200
remainder %= 200
若 frame >= 帧数：frame = 0
```

超过帧数时直接归零，不能对帧数取模；但毫秒余数会保留。与地图普通图片的300ms更新器不同，不能共用那个丢余数的循环。每个角色部件各自推进，宿主不再靠单个全局帧序号驱动不同帧数的部件。

结果控制器 `0x00613560` 在等待/下落/淡入分派之前就更新角色，所以动作从结果初始化便开始播放，包含最初3秒等待。首次显示时不是重新从第0帧开始。
