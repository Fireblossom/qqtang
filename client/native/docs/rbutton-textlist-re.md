# 右键事件与聊天记录里的名字、链接

2026-11-17，静态逆向 `gameUI.dll`、`QQTSection.dll`。代码在 `qqtclient/runtime.py`（分发）、`qqtclient/textlist.py`（标记解析、排版、命中）、`qqtclient/render.py`（TEXTLIST 绘制）、`qqtclient/chat.py`、`qqtclient/kin.py`（生成带名字标记的行）、`qqtclient/natives.py`（`Win_GetRect` 906）。测试在 `tests/test_textlist.py`。

## 一、事件号

回调名表在 `0x100471D8`，下标就是 `FUN_1002e949`/`FUN_1002e836` 的参数加 3（它们取 `0x100471E4 + 4×参数`）：`OnClick` 7、`OnRBtnUp` 8、`OnMouseMoveIn` 9、`OnMouseMoveOut` 10、`OnDBClick` 17、`OnRClick` 29。

消息分发 `0x100304C8` 把 Windows 消息变成控件输入码，调用控件虚表 `+0x18`（参数：输入码、wParam、lParam）：

| 消息 | 输入码 | 目标 |
| --- | --- | --- |
| WM_LBUTTONDOWN 0x201 | 6 | 命中检测（有捕获根 `+0x2B4` 时从它开始，没命中就给它本身）；先关掉点在外面的弹窗 |
| WM_LBUTTONUP 0x202 | 7 | 按下的控件等 |
| WM_LBUTTONDBLCLK 0x203 | 8 | 命中检测；先关弹窗 |
| WM_RBUTTONDOWN 0x204 | 9 | 命中检测；先关弹窗（与左键同一段 `+0x2A8`/`0x10028C60` 判断） |
| WM_RBUTTONUP 0x205 | 10 | 命中检测；**不看按下的是谁**，没有右键捕获 |
| WM_MOUSEMOVE 0x200 | 11/12/13 | 同时把鼠标位置记到 `[0x10048AC0]`、`[0x10048AC4]` |

## 二、右键按下：OnRClick

- 基类输入方法 `0x1002ADEB` 的 case 9：先 `0x1002E247` 隐藏控件的 `buddy_widget_infowgt`（编号 5，`0x10026D8B` 按 `buddy` 表查；脚本里只有 `UI` 声明了 1、2、3 号，所以实际什么都不做），再 `FUN_1002e949(this, 0x1A, "")` 发 `OnRClick()`，不往父控件传。
- 按钮类（`0x10004321`）、KEYEDIT（`0x10014AC9`）等对 9 都转给基类，所以它们都在**按下**时收到 `OnRClick`。宿主以前在抬起时发，已改为按下时发。
- TEXTLIST（`0x10023F0A`）自己处理 9：只在名字上发 `OnRClickName`（见第四节），不发 `OnRClick`。

## 三、右键抬起：OnRBtnUp

- `0x10004321` 的 case 10：`sprintf("(%d,%d)", x, y)`（格式串 `0x10046210`，x、y 是 lParam 的客户区坐标）后 `FUN_1002e949(this, 5, …)`，即 `OnRBtnUp((x, y))`；脚本写成 `def OnRBtnUp(pos): x, y = pos`。
- 用 `0x10004321` 的类：BUTTON、SPIN（虚表 `0x1003C500`、`0x1003C6B8` 的 `+0x18` 直接是它）、MENUITEM（`0x100070D4` 转发）、CHECK（`0x10004A03`）、CHANGEBAR（`0x100082BE`）。KEYEDIT 的 case 10 当作"鼠标右键"按键（`Mouse_R`，宿主原有 `keyedit_click(right=True)`）。
- 其他类对 10 都落到基类 `0x1002ADEB` 的 default，**交给父控件的 `+0x18`**。所以抬起时点在按钮的非 Static 子控件（如标签）上，也是按钮收到 `OnRBtnUp`。
- 脚本用法：大厅玩家列表 `playerInfo1..16`（`uiSelRoom.py` 约 2741）、引导栏好友/玩家列表（`uiMain.py` 约 2907）在 `OnRBtnUp` 里把 `UI.playerMenu` 移到鼠标处并显示；家族成员行 `MemberPlayer0..`（`uiMain.py` 约 3689）显示 `kinOprMenu`（职位提升/下调走 `DoKinTask(…, 2)`，开除先弹确认再走任务 5，非族长时开除被禁用）。这是界面上提升、下调、开除成员的唯一入口。

## 四、TEXTLIST 的行结构和标记

- 每行是一个对象（`0x1002289D` 构造，`+4..+8` 是 0x50 字节元素的 vector）：元素 `+0` 类型、`+4` 值、`+8` 宽度、`+0xC` 附加、`+0x10` 源文本。构造时逐字节建元素（`0x10022C0C`：单字节为 0，双字节先 3 后合成 1），然后 `0x10022CA3` 从头扫描。
- 只有"前一个元素不是普通 `/`"的 `/` 才解析（`0x10025B3F`）。解析器 `0x100231AA` 取其后 64 字节：
  - `/<name=N:uin=U>`：类型 10，值为 uin，`+0xC` 为 N；之后 N 个字节保留为普通字符、不再解析（名字里的 `/` 不会变成表情）。
  - `/<kin=K>`：类型 0xB，宽 0x14；K ≥ 0 时加载 `object/ui/kinTotem/%03d.img`（`0x10047160`）存到行 `+0x2C`，K < 0 不画但 20 像素照占。
  - `/<level=P>`：类型 0xC，宽 0x14；执行脚本 `ui_GetLevelMainPath(P)`、`ui_GetLevelSubPath(P)`（`0x10047148`、`0x10047130`）得到两张图。
  - `/<H>`、`/<h>`：类型 8 值 8（链接开始）；`/<~H>`、`/<~h>`：类型 8 值 0（链接结束）。
  - `/<C=RRGGBB>`、`/<~C>`（颜色，类型 5）、`/<img=…>`（0xD）、`/<eft=…>`（0xE）：解析器认识，但 `0x1002350A` 只在行的标志字节 `+0x10` 允许时保留（2 颜色、0x10 链接……），而 `0x10022938` 把它设成 0x10，所以 TEXTLIST 里只有链接生效，颜色等标记落到表情查找、按原文显示。宿主同样不实现颜色。
  - 其他 `/` 按表情码查找（`0x10018F2D`，表顺序第一个匹配）。
- 排版 `0x100236F0`：双字节字符宽为 textsize，单字节按字体量（宿主用宋体半宽），表情用自身宽度，kin/level 用存的 20，名字和链接标记宽 0；累计宽度超过可用宽度时在该元素前换行；行高 textsize + rowspace。
- 绘制 `0x10023551`：kin 图、level 主图和副图都画在 (x+2, y−5)，帧号为行计时 `+0x38` ÷ 150。宿主用全局时间 ÷ 150 取帧（行计时的起点没追，推断差别看不出）。

## 五、TEXTLIST 的点击

三个处理函数都先把列表文本（`+0x2B4`）清空，然后对每一行、每个完全落在显示区内的子行（宿主用 `Renderer.list_rows()` 的位置，与绘制和滚动条同一套排版，见 `scrollbar-re.md`；`Renderer.textlist_hit_rows` 只留完全在客户区内的子行），按 y ∈ [行顶, 行顶 + 行高] 找子行，再找第一个 [x, x + 宽] 含鼠标 x 的元素：

- 左键按下 `0x10024190`（输入码 6，TEXTLIST 自己处理，基类的按下逻辑不跑）：
  - 从该元素往前找最近的类型 8：是开始（值 > 0）时，取到下一个结束标记（没有就到行尾）之间的源文本作为 url，`OnClickHLink(url)`，结束，不发 `OnClick`。
  - 否则用 `0x10023966` 找名字：往前找最近的类型 10，从它后面到当前元素的字节数 ≤ N 才算在名字里。是名字就 `OnClickName('名字', uin)`（名字取标记后的 N 个字节，`0x10023A0D`，引号已转义；uin 用 `%u`），循环结束后照常 `OnClick()`。
  - 点在不属于名字的字符或图标上：**直接返回，什么都不发**。
  - 没点到任何元素（行尾右边、空白处）：`OnClick()`。所以 TEXTLIST 的 `OnClick` 在按下时发；抬起（输入码 7，基类）只清按下状态。宿主已照做。
- 右键按下 `0x1002495A`：只在名字上发 `OnRClickName('名字', uin)`，其余什么都不发。
- 双击 `0x10024D10`：只在名字上把列表文本设为 uin 的十进制（`_ultoa`），再发 `OnDBClick('路径')`；脚本用 `Win_GetText(me)` 读到 uin 插进聊天输入框。宿主的 TEXTLIST 不再把 `text` 画出来（原版绘制不画 `+0x2B4`，推断）。
- 鼠标移动 `0x100246AA`：在名字上把光标换成 `Click`，否则 `normal`。宿主没有自绘光标，没做。
- 原版 bug，已修正：链接补 `http://` 时用 `basic_string::compare(0, 全长, "http://", 7)`（`0x10024646`），比较的是整串，只有正好等于 `http://` 才相等，所以已经带 `http://` 的链接会变成 `http://http://…`。宿主改为按小写前缀判断，没有前缀才补。

`OnRClickName` 用 `Win_GetRect(me, 906)` 定菜单位置。`Win_GetRect`（`0x1001CBAD`）对 0x22～0x25 返回控件的几个矩形，对 0x38A（906）返回最近一次 WM_MOUSEMOVE 的坐标、宽高 0，与控件无关。宿主以前对 906 返回 (0, 0, …)，菜单跑到左上角；已改。宿主的自动点击不产生移动事件，所以按键时也更新鼠标位置（真实鼠标总是先移到那里）。

## 六、谁生成带标记的行

- 大厅聊天（`QQTSection` `0x1001F3D6`）：消息体在 `说:`（3 字节，`0x1005EA88`）处拆开（`0x1002B1FA`：位置在 1～19 字节才算名字，否则名字就是 `说:`、正文是整条），身份和本机标志都不含 0x70706/0x70006 时组成 `"/<kin=%d>/<level=%d>/<name=%d:uin=%u>%s%s"`：kin 取 KINFLAGID 的旗号（消息 `+0x41A`，0～0x30 之外为 −1），level 取积分（`+0x412`），N 为名字字节数，最后是名字和"说:正文"。宿主 `textlist.lobby_line` 照此生成，`net/chat.py` 已解析积分和旗号。其他身份（GM 等）的格式（`0x1001F94B`）没有追。
- 悄悄话（`0x10026EFF`）：`"/<name=%d:uin=%u>%s[%u]%s"`，后面是 `悄悄的说: %s`（`0x10062268`）。宿主保留原有措辞"X悄悄对你说:"，只在前面加名字标记；在商城里弹框显示时不加。
- 家族聊天（`0x10016C8A`）：`"/<name=%d:uin=%u>%s[%u]说:%s"`，宿主 `kin.py` 照此加标记。
- 这三处之外的 `/<name=` 格式串只有 `0x100623C8` 一条（没有引用）。房间聊天的生成函数没有追，宿主房间聊天行不加标记；推断原版房间聊天里只有悄悄话和家族聊天的名字可点。
- 玩家自己输入的 `/<H>`、`/<h>` 会被脚本 `filterChatMsg` 去掉，链接只来自系统消息。

## 七、实测

测试服 58000。1000013 在大厅发两句话（其中一句带 `/<H>www.qq.com/<~H>`），1000012：

- 聊天行显示为 20 像素空位（无家族）+ 等级图标 + "测3说:…"，链接文字正常显示、标记不显示。
- 左键点"测3" → `OnClickName 测3 1000013`，聊天模式切成对测3密语；双击 → 输入框插入 `1000013`；右键 → `[OnRClick]`，玩家菜单出现在鼠标右侧 30 像素；菜单"查看资料"打开测3的资料；点链接 → `OnClickHLink` 切到 web 界面（宿主没有 `JumpHelpWeb`）。
- 右键玩家列表里的测3 → 菜单出现在鼠标处，"发送密语"后再发言，1000013 收到"测2悄悄对你说"（带名字标记，不显示原文）。
- 1000005（族长）打开家族成员页，右键 1000006 那一行 → `kinOprMenu`；"职位提升"后弟子变护法，再"职位下调"恢复弟子。没有测开除。
