# 探险路线复用与地图元素方向谓词

2026-11-04。接续 `pve-astar-re.md`：新建路线和复用旧路线对地图元素采用不同条件，不能共用“占格就是阻挡”的判断。

`0x005F0FC1` 新建路线要求地图元素的通行谓词非零；`0x005BB7F6` 校验旧路线反而在谓词非零时返回无效。此前已用受控谓词确认复用函数的调用顺序，但正式宿主适配器仍直接拒绝所有占格元素，未真正使用对应方向位。

新探针 `probe_pve_route_elements.py` 完整初始化PVE角色后设置明确的位置(300,260)，安装三节点路线；世界元素/炸弹查询与元素GridAttr查询受控，元素虚表指向真实 `0x007A369C`，实际执行 `+0x2C = 0x005EF1AA` 及真实 `0x005BB7F6`。元素对象仅提供本次通行所需的真实虚表，不声称构造了完整原生地图对象/世界。

- 原版基础谓词对方向0/1/2/3读取GridAttr的8/4/2/1位。
- 路线当前格或中间格：对应位为1时旧路线无效，位为0时可保留；这是原版的反向条件，未改成更符合直觉的逻辑。
- 末节点方向9：真实谓词直接返回低字节0，不查GridAttr，因此该基础元素位于终点时不导致旧路线无效。
- 空场景基线必须有效并保留当前格节点，防止把角色位置不匹配导致的查找失败误记成元素效果。

正式 `adventureReuseRoute` 现在按上述基础方向位和末节点规则判断；原有炸弹、战斗目标与前缀消费顺序不变。特殊地图对象若覆盖了这个虚函数，仍需继续逐类核对，此处结论限于已验证的基础CMapElement属性适配。
