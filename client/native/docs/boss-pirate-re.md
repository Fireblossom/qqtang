# 海盗 Boss 技能解释器、石化波、变身道具 110（Client.exe 静态逆向）

范围：RoleID 33（大副）、34（虎克船长）的技能解释器 `0x005B2AC1`，以及通用技能 2（石化波）、3（变身道具 110）的完整效果。
接着 `boss-ai-re.md`（AI 控制器、寻路、通用技能 1～4、0x1169 接收方）和 `boss-lifecycle-re.md`（创建、受伤、死亡）往下写，记号沿用：

- **N**：Boss 角色对象；**G** = `N+0x3fc`（角色管理器，`G+0x3838` 游戏时间 ms）；**S** = 场景对象（`G = S+0x1310`）；**P** = `N+0x400` 属性对象。
- **[汇编]**：已用 capstone 核对原始指令；**[伪C]**：只读了 Ghidra 伪 C；**[推断]**：有依据但没追到底。
- `0x005D9BBF(...,400,0)`、`0x005D3C1D(...,400,0)` 的 400 是飞行速度 **400 px/s**，不是毫秒。

---

## 0. 结论摘要

1. 海盗解释器**不看 BOSS_INFO.Skills**。创建时 `0x005B37C0` 按 RoleID 从 `0x007F2A20`（33）或 `0x007F2AD4`（34）抄入 5 套脚本，每套 9 个 DWORD，0 表示空位 [汇编，数据已导出]：

   | 脚本 | 大副 33 | 虎克 34 |
   |---|---|---|
   | 0 | 9, 4, 6 | 9, 4, 5, 6 |
   | 1 | 6 | 6 |
   | 2 | 6 | 6 |
   | 3 | 6 | 8 |
   | 4 | 7 | 7 |

   服务端发什么技能号都不影响海盗的行为。目录里的 `{4,6,7,9}` / `{4,5,6,7,8,9}` 只是脚本里出现过的技能号集合，不会被客户端读取。
2. **一次调用跑完整套脚本**：脚本里的技能在同一帧、用同一个 Time 依次放出。某个技能条件不满足时**整套中止**，脚本序号不前进，下次重跑**同一套**（前面已经放出的技能不会撤回）。脚本全部成功，序号 `N+0x7b0` 才加 1（模 5 取用）。
3. 时间闸门：游戏时间 ≥ 5000 ms；距"上一个放出的技能"≥ 5000 ms；上一个技能是 7 时还要求距技能 7 ≥ 15000 ms。**没有其他冷却**（技能 1～3 的 10 s/30 s 冷却只对脚本里没有的 1～3 有效）。
4. 技能含义：**4** = 往 5 个随机空格扔陷阱（场景 41）并喊"电光雷亟"；**5** = 所有玩家禁止放泡；**6** = 两波落泡（2k 个威力 2 的泡 + k 个威力 5 的泡，k = min(时间/16 s + 5, 15)），并喊一句咒语；**7** = 空消息，让下一套脚本至少等 15 s；**8** = 解除禁泡；**9** = 不发消息，只记时间（相当于 5 s 停顿）。
5. 大副独有的血量门槛：技能 4 要求 HP < 8，技能 6 要求 HP ≤ 4。HP=10 时大副卡在脚本 0（每 5 s 空转一次技能 9）；HP 降到 5～7 后每 5 s 扔一次陷阱；HP ≤ 4 才进入落泡循环。虎克没有血量门槛。
6. 技能 6 的接收方对**每个泡**调用一次 `S+0x10` 随机数，决定泡从本行最左格（col 0）还是最右格（col 14）飞入。这只影响各端看到的飞行路线和落地时间，落点由消息决定。这和踢炸弹空投 `0x006018A7` 是同一套做法，可以直接复用 `kickbomb.go` 的 `DropRuleBatch` + `FromCol`。
7. 石化（通用技能 2）：目标的状态机切到状态 11（时长 10000 ms），模式字节 `+0x3b7 = 10`，`+0x3d0 = 10000` 倒计时；avatar 循环播放动作 3（`sit`），朝下。石化期间**不能移动、不能放泡，能被炸成困泡**；Boss 的"追杀被困玩家"会把石化的玩家当成被困者来追，但接触击杀要求状态 5，所以碰到石化的玩家不会直接击杀。约 10 s 后 `+0x3d0` 倒计时把模式恢复为 1。
8. 变身道具 110 = **小恶魔**（变身类型 42，模型 `player42.ini` → `body14201`）。持续 30000 ms；移动档 8；同时最多 8 个泡；威力不变；**Boss 不反向**（普通玩家方向键反向）；装上后 3 s 免伤。被炸到只会解除变身、不扣血；仲裁方本机另给 3 s 免伤和闪光。变身期间全局泡泡引信是 2500 ms（`0x005B0BAF`）。
9. 副作用（与死亡相关）：Boss（RoleID 24/28/≥29，规则不是 12）死亡时 `0x005B9390` 给**所有角色**的禁泡计数 `P+0x28c` 加 1，用的就是技能 5 那个计数器。

## 1. 海盗解释器 `0x005B2AC1`

### 1.1 调用时机 [汇编]

- AIType 3（`0x005DF058`，目录里 33/34 用的就是 AIType 3）：前四步（追杀被困玩家、逃离危险、追活玩家、捡道具）都失败、RoleID 是 33/34 时才调用。AIType 4（`0x005DF13A`）是在 `followPath() != 0` 时调用。
  - **结论：只有当 Boss 走不到任何玩家、附近也没有道具时，海盗才会尝试放技能**。和通用技能一样（`boss-ai-re.md` §3.2），技能只在这种"无事可做"的决策帧里被检查；但闸门按游戏时间算，所以一旦落到这一步就会立刻补放。
- 只有仲裁方跑 AI。决策约每 7 帧一次（返回 9 时每帧一次）。

### 1.2 状态字段 [汇编]

| 偏移 | 含义 | 初值（`0x005AFDFA`） |
|---|---|---|
| `N+0x7b0` | 脚本序号（取用时 `% 5`） | 0 |
| `N+0x7b4` | 上一个放出的技能号 `last` | **1** |
| `N+0x77c + 4*s` | 技能 s 上次放出的时间 `t[s]`（s=4..9：`0x78c 0x790 0x794 0x798 0x79c 0x7a0`） | 创建时的游戏时间 |
| `N+0x7bc/0x7c0` | 脚本 vector（每项是 16 字节的 `vector<int>`，9 个元素） | `0x005B37C0` 填入 |
| `N+0x830` | 每次调用都被改写成脚本长度 9（原本是 BOSS_INFO.Skills 的数量，海盗用不到） | |

注意：技能 1、2、3 的计时器和 `t[s]` 错开了一格（技能 1 写 `0x784` = `t[2]`，闸门却读 `t[1]` = `0x780`，而 `0x780` 每次调用开头都被清零）。脚本里没有 1～3，所以不影响；移植时 4～9 用 `t[s]` 即可。

### 1.3 伪代码（可直接照抄）

```
pirateSkills():                                    // 0x005B2AC1
  now = G.time                                     // G+0x3838
  if now < 5000: return                            // jb 0x1388
  if last == 7 && now - t[7] < 15000: return       // 0x7b4==7, 0x798, jb 0x3a98
  N+0x780 = 0
  body = zero(0x18d)                               // 0x1169 消息体，见 1.4
  body.ObjectID = N.id; body.Time = now
  body.PosX = int(N.x); body.PosY = int(N.y)       // ftol，向零取整
  if last <= 0 || now - t[last] < 5000: return     // jle / jb 0x1388（无符号比较）
  script = scripts[N+0x7b0 % 5]                    // 9 项
  for s in script:
    if s == 0: continue
    body.SkillID = s
    switch s:
    case 4:
      if N.role == 33 && HP() >= 8: abort          // HP() = 0x005AA8E8(P)；cmp ax,8; jge
      cells = randomFreeCells(5)                   // 0x005B8574，全图（规则 12 才用 vtbl+0xb8 的矩形）
      if len(cells) < 5: abort
      body.Count = 5; body.Items = [{41, r, c}]
      send1169(body)
      last = 4; t[4] = now                         // 0x78c
      send116A("    无云的晴空,迟与快的组合!遵从电与火之古老契约!去触击他!--电光雷亟!")  // 0x007F2A14→0x7F2CDC，len 69
    case 5:
      body.Count = 0; send1169(body)
      last = 5; t[5] = now
    case 6:
      if N.role == 33 && HP() >= 5: abort          // cmp ax,5; jge
      k = min(G.time / 16000 + 5, 15)              // 0x005E181C（ecx = G+0x1358，读 [ecx+4]+0x3838）
      cells = randomFreeCells(2*k)                 // 字节截断：(k<<1) & 0xff，k ≤ 15 所以无影响
      if len(cells) < 2*k: abort
      body.Count = 2k; body.Items = [{1, r, c}]    // 威力 2 的泡
      send1169(body)
      k = min(G.time / 16000 + 5, 15)              // 重新算一次（同帧，值相同）
      cells = randomFreeCells(k)
      if len(cells) < k: abort                     // 注意：此时第一波已经发出
      body.Count = k; body.Items = [{2, r, c}]     // 威力 5 的泡
      send1169(body)
      last = 6; t[6] = now                         // 0x794
      send116A("    比黑暗还要漆黑者,比夜晚还要深沉者,混沌海中最虚无的的存在,依循着魔界碎片之缘,降临人界")  // 0x007F2A1C→0x7F2BE8，len 88
    case 7:
      body.Count = 0; send1169(body)
      last = 7; t[7] = now                         // 0x798
    case 8:
      body.Count = 0; send1169(body)
      last = 8; t[8] = now                         // 0x79c
    case 9:
      last = 9; t[9] = now                         // 0x7a0，不发消息
    // case 1/2/3 也存在（与通用解释器相同，冷却 10 s/30 s/30 s，技能 2 喊"\t 石化波！！！"），脚本里没有
  N+0x7b0 += 1                                     // 只有整套跑完才执行
abort: return                                      // N+0x7b0 不变，last/t[] 保留已放出技能的更新
send1169(b) = 0x005A1DE1/0x005A2F4C 上行 + 0x005C8794/0x0087960B 本地分发
send116A(text) = {u16 N.id, u16 strlen, GBK 文本}，同样上行 + 本地分发（接收方 0x005FDA38 什么都不显示）
```

跳转表 `0x005B379C`（SkillID-1 → 入口）[汇编]：1 `0x5B2C9F`、2 `0x5B2E33`、3 `0x5B2FFB`、4 `0x5B307F`、5 `0x5B3627`、6 `0x5B3289`、7 `0x5B36DC`、8 `0x5B3683`、9 `0x5B3735`。

### 1.4 0x1169 消息体（与通用解释器相同）

| 偏移 | 字段 |
|---|---|
| +0x00 u16 | ObjectID（Boss ID；技能 2 时改成目标 ID） |
| +0x02 u32 | Time（本次调用开头的 `G+0x3838`，整套脚本共用） |
| +0x06 u16 / +0x08 u16 | PosX / PosY（Boss 像素坐标） |
| +0x0A u16 | SkillID |
| +0x0C u8 | Count（≤ 64） |
| +0x0D 起 | Count × `{u32 SceneID, u8 row, u8 col}` |

消息体在整套脚本里复用：技能 5、7、8 显式把 Count 清零，但 Items 字节不清（接收方不看）。

### 1.5 实际节奏

以"每次落到技能步骤时闸门都已打开"为前提：

**虎克（34）**，没有血量门槛：
- t0：脚本 0 = 9、4（5 个陷阱 + 台词）、5（禁泡）、6（两波落泡 + 台词），同一帧放出。
- ≥ t0+5 s：脚本 1，落泡。
- ≥ +5 s：脚本 2，落泡。
- ≥ +5 s：脚本 3，技能 8 解除禁泡。所以禁泡**至少约 15 s**。
- ≥ +5 s：脚本 4，技能 7。
- 之后至少等 15 s，回到脚本 0。

**大副（33）**，按 HP 分三档：
- HP 8～10：脚本 0 的技能 9 成功（last=9），技能 4 中止。每 5 s 重复一次，**什么也不放**。
- HP 5～7：脚本 0 的 9、4 成功（扔陷阱 + 台词），技能 6 中止（last=4）。**每 5 s 扔一次陷阱**，脚本不前进。
- HP ≤ 4：脚本 0 全部成功，之后脚本 1～3 每 5 s 落泡一次，脚本 4（技能 7）休息 15 s，然后循环。

**空格不够时**：如果技能 6 的第二波格子不够（k 个），第一波已经发出，但 last、t[6] 都没更新，脚本也不前进。只要 `t[last]` 已经超过 5 s，**下一个决策帧就会再来一次**，可能连续刷出第一波。地图很满时才会遇到 [汇编，按控制流推出]。

## 2. 0x1169 接收方 `0x005FDB18`：海盗相关分支

跳转表 `0x005FE07A`（SkillID-1）[汇编]：1/10 → `0x5FDB9F`，2 → `0x5FDC47`，3 → `0x5FDC57`，4 → `0x5FDCD9`，5 → `0x5FDE8E`，6 → `0x5FDD7B`，8 → `0x5FDEF6`，11 → `0x5FDF5E`，12 → `0x5FDF84`，**7 和 9 → `0x5FE05D`（直接返回，无效果）**。SkillID > 10000 忽略。`role = 0x005A287F(ObjectID)`。所有客户端（包括仲裁方的本地分发）都执行。

### 2.1 技能 4：陷阱 [伪C，与技能 1 同一段代码]
对每一项：`obj = 0x005CB79A(41)`，起点设为 Boss 所在格 `(PosY/40, PosX/40)`（`0x005CCE0A`，有符号除法），登记（`0x005D9A79`），然后 `0x005D9BBF(obj, row, col, 400, 0)` 以 400 px/s 飞到目标格。场景 41 被非 Boss 踩到时，等同被炸困住（本地分发 0x0FA5），见 `boss-ai-re.md` §7.2。

### 2.2 技能 5 / 8：禁泡 / 解禁 [汇编]
```
case 5:                                  // 0x5FDE8E
  if S+0x4b34 != 0: S+0x4b38 = S+0x4b34  // S+0x4b34 推断为本机玩家角色，S+0x4b38 是当前操控/观战的角色
  (S+0x4b38)->P->0x005AA2CE()            // P+0x28c（加密 int）+= 1
  for r in 全部角色 (S+0x2648 = G+0x1338): r+0x424 = 1
case 8:                                  // 0x5FDEF6
  同样先改 S+0x4b38
  (S+0x4b38)->P->0x005AA2FB()            // P+0x28c = 0
  for r in 全部角色: r+0x424 = 0
```
- `P+0x28c ≥ 1` 时，可用泡数 `P->vtbl+0x2c`（`0x005AA1B5`，以及 `0x005AAB3B`）直接返回 0，所以**这个角色不能放泡**。每个客户端只锁**自己的**玩家，合起来就是所有玩家都被锁。Boss 不受影响（它不是本机玩家）。场上已有的泡照常爆炸。
- 技能 5 是"+1"，技能 8 是"清零"，所以两次技能 5 之后只需要一次技能 8 就能解锁。
- `r+0x424` 是角色上一个附加组件 `+0x428` 的绘制开关（绘制函数 `0x005AC6A2`、`0x005AEE1D`、`0x005AF099` 都检查 `+0x428 != 0 && +0x424 != 0`）。但 `+0x428` 在普通代码里**只有初始化为 0 和析构**，没找到创建它的地方，推测在加壳区，或者根本不创建。所以禁泡期间是否有头顶图标 [未知]。
- 同一个计数器的其他 +1 来源：`0x005B9390`（Boss 死亡时给全部角色 +1，见 §0 第 9 条）、`0x005F8624`、`0x005FA37A`、`0x0061B228`。其他清零来源：`0x005F8677`、`0x005FA37A`、`0x0061B1BB`。

### 2.3 技能 6：落泡 [汇编]
```
case 6:                                          // 0x5FDD7B
  if Count > 64: return
  type  = Items[0].SceneID                       // body+0x0D 的 DWORD，整条消息共用
  power = (type == 2) ? 5 : 2                    // setne; dec; and 3; +2
  boss  = role(ObjectID)
  for it in Items:
    b = 0x005CC58F(type, boss.P+0x274, boss.P+0x278)   // 泡工厂；0x005CB087 预载资源
    b+0x1c = ObjectID                            // 归属 Boss
    b+0x24 = body.Time                           // 放置时间 = 施法时间（引信从这里算 [推断]）
    b+0x1e = power
    b+0x20 = boss.P->vtbl+0x24()
    fromCol = (RNG_S10() & 1) == 0 ? 14 : 0      // 0x0040F722 → 0x004522F0，每个泡、每个客户端各调一次
    b->0x005DF590(it.row, fromCol)               // 先放在本行的边缘格
    G+0xf40->0x005D388A(b, 0xffff, 0xffff)       // 加入泡泡管理器（S+0x2250）
    G+0xf40->0x005D3C1D(b, it.row, it.col, 400, 0)   // 以 400 px/s 水平飞到目标格
```
- **对 RNG 的影响**：每个接收方对每个泡调用一次 `S+0x10`（与 ItemSeed/SpawnSeed 同一个 LCG）。仲裁方本地分发时也会调用。所以一次技能 6 会让每个客户端的发生器前进 3k 步（以每个客户端各自的发生器为准）。各端选到的边缘不同，只影响飞行动画；落点和归属一样。飞行时间 = |col − fromCol| × 40 / 400 s，即 **每格 100 ms**（`battleengine.NativeBombFlightMSPerCell`）。
- 这与踢炸弹空投 `0x006018A7`（`kickbomb.go` 的 `kickRule.apply`）是同一个机制：场景 1 威力 2、场景 2 威力 5，从本行一端飞入。移植可以直接用 `engine.DropRuleBatch(bossID, Time, bombs{Cell, Power: wire-1, FromCol}, nil)`。
- 第二波选格时，仲裁方本地分发的第一波是否已经进了泡泡管理器（这决定 `0x005B8574` 是否避开第一波），取决于本地分发 `0x005C8794`/`0x0087960B` 是不是同步执行。踢炸弹的注释说它经过加壳的消息对象、在一帧内执行 [推断]。如果是异步的，第二波可能和第一波落在同一格。

### 2.4 技能 7 / 9
接收方没有分支，没有效果。技能 9 根本不发消息。技能 7 发出一条 Count=0 的 0x1169，只是为了在 `last=7` 时触发发送端的 15 s 闸门。

### 2.5 台词 0x116A
接收方 `0x005FDA38` 把消息交给一个空函数，**原版不显示任何台词**（见 `boss-lifecycle-re.md` §3.3）。仲裁方仍然按上面的顺序发出：技能 4 的台词在 0x1169 之后，技能 6 的台词在两波 0x1169 之后。`0x007F2A18`（虎克遗言）、`0x007F2A08`（"送点礼物给大家！"）没有代码引用。

## 3. 通用技能 2：石化波

### 3.1 进入 [汇编]
接收方 SkillID 2：`target->(+0x36c 状态机)->0x005C0A9F()`：
```
old = cur->vtbl+0x34()                 // 当前状态号
cur = 0x005C0AD3()                     // 单例 0x0085FFB0，虚表 0x007A2160
if old != 11: elapsed(+8) = 0
cur->vtbl+0x18(target)                 // 0x005C0E22 → target->0x005ACC11()
```
石化状态（虚表 `0x007A2160`）：`+0x30` 时长 = **10000 ms**（`0x005C0E2E`），`+0x34` 状态号 = **11**（`0x005C0E34`），`+4` 超时 = `0x005C0E0B`，`+0x18` 进入 = `0x005C0E22`。

`0x005ACC11`（进入时执行）：
```
target+0x3d0 = 10000                   // 模式倒计时
(target+0x318)->0x005B4F3E()           // 删掉 +0x318 组件上挂着的特效（+8，例如免伤闪光），avatar(+4) 播动作 3、循环 -1、朝向 270°（下）
target+0x3b8 = 1                       // 停止
target+0x3b7 = 10                      // 模式 10
```
动作号对应名字表 `0x007DA010`：0 空、1 stand、2 trigger、**3 sit**、4 walk、5 ride、6 die、7 freeze、8 lose、9 jump、10 win、11 wait、12 faint、13 slow、14 birth（birth=14 与 `boss-lifecycle-re.md` 一致）。所以石化的画面是**循环播放 `sit` 动作并朝下**，没有额外的特效图。普通人物的 `cloth*_sit.img` 都在 `object.pkg` 里，例如 `object/cloth/cloth10101_sit.img`。

### 3.2 石化期间（模式 10）能做什么 [汇编/伪C]
| 行为 | 结果 | 依据 |
|---|---|---|
| 移动 | 不能。移动命令要求 `+0x3b7` 为 1 或 0x0B | `0x006112AF`、`0x005AC982` |
| 放泡 | 不能。`0x005AD009` 在模式不是 1 时返回 0 | `boss-ai-re.md` §4 |
| 被炸 | **能**。`0x005AD175` 接受模式 1、10、11，被炸后照常进入困泡（0x0FA5） | `0x005AD175` |
| 被 Boss 接触 | 不会被击杀。`0x0060C148` 要求状态 5（`0x005AD1D9`），石化是状态 11 | |
| 被 Boss 追 | 会。`0x005B190A` 把模式 3 或 0x0A 当成被困者来追（路径 ≤ 10），然后 `playerInLine` 让 Boss 在旁边放泡 | `boss-ai-re.md` §3.1 |
| 选为石化目标 | 不会重复选中：技能 2 只选模式 1、没有变身的非 NPC 角色 | |

### 3.3 结束
- **模式**：`0x005AE618(dt)` 在 `+0x3d0 ≥ 0` 时每帧减 dt。减到负数（并且大于 -5000）时，把它设为 -5001，并令 `+0x3b7 = 1` [汇编]。这个函数在普通代码里**没有调用方**（也没有指针引用），推测由加壳区的每帧角色更新调用 [推断]。所以石化大约 10000 ms 后恢复。
- **状态机**：`0x005C0743(dt)`（NPC 由 `0x005ABE96` 调用；玩家推测走同一个状态机）累计 elapsed。到 10000 ms 时调超时 `0x005C0E0B` → `0x005C07FE(target.dir)`，切到行走状态（状态号 3，虚表 `0x007A20B8`），进入函数是 `0x005AC982`。但 `0x005AC982` 只在模式为 1/0x0B 时才生效：如果状态机先于模式倒计时到期，切换后人物仍是停止状态，avatar 可能还停在 `sit`，直到玩家按方向键 [推断：同一帧里两个计时器谁先谁后没查]。
- **可能的原版 bug** [推断]：困泡不会改 `+0x3d0`。石化中被炸成困泡的玩家，在 10 s 倒计时结束时模式会被改回 1；而移动命令调 `0x005C07FE` 时不检查状态 5，所以这名玩家可能直接"走出"泡泡。需要录像核对。
- 没有找到任何"提前解除石化"的途径（`0x005ACC39` 是救人 0xFAB 和道具回调用的，只用于困泡）。

### 3.4 移植要点
- 服务端/边车只需要转发 0x1169（SkillID 2，ObjectID=目标）。各端自己执行：目标 10 s 不能动、不能放泡，可以被炸，模型播放 `sit`。
- 目录目前故意没有给任何 Boss 配技能 2，海盗脚本里也没有。

## 4. 通用技能 3：变身道具 110（小恶魔）

### 4.1 消息链 [汇编]
1. 仲裁方的技能解释器发出 0x1169（SkillID 3，ObjectID = Boss）。
2. 接收方 SkillID 3（`0x5FDC57`）只在仲裁方执行（`S+0x4b34 == S+0x4b40`），发送 `0xFAC {u16 BossID, u32 G.time + 1000000, u32 0x6E, u16 int(x), u16 int(y)}`：上行，并且本地分发。
3. 0xFAC 处理 `0x0060546B`，只在仲裁方执行：时间在 [1000000, 1999999]、道具在 0x66..0x72（102..114）时**不查地面**，直接回 `0xFAD {u16 id, u32 time, u32 item, u16 x, u16 y}`，上行并本地分发。所以 +1000000 是"技能发放道具"的标记。
4. 0xFAD 处理 `0x00604DB0`，所有客户端都执行，进入同一分支：`obj = 0x005CB79A(110, 规则号)`（构造 `0x005CEB13`，虚表 `0x007A2FA0`），`obj+4 = 0`（不在场上），`obj->vtbl+0x20(boss)`，然后析构。
5. 道具 110 的拾取回调 `0x005CEB53`：`t = 0x005F767D(boss, 0x2A)`，`boss->0x005ADF5A(t)`。

所以服务端或边车必须把 0xFAD 发给所有客户端（0xFAC 只发给仲裁方即可）。目前移植里的 `boss_ai.go:750` 还只记日志。

### 4.2 变身对象（类型 0x2A = 42，构造 `0x00611BAC`，虚表 `0x007A48F8`，基类 `0x005F786E`/`0x007A3C0C`）[汇编/伪C]
| 槽 | 函数 | 含义 |
|---|---|---|
| ctor | `0x005F786E` | `+0x34` 剩余时间 = **30000 ms** |
| +0x04 | `0x00611BEB` | 安装：`vtbl+0x60(0x2A)` 建 avatar = `0x005CB15C(42, TeamID-1)`，也就是 `object/player/player42.ini`（`body = 14201`、`leg=1`，图片 `object/body/body14201_stand.img`/`_walk.img`）；然后在变身对象上 `0x005B5202(3000)`，**3 s 免伤** |
| +0x28 | `0x005F7931(dt)` | `+0x34 -= dt`（NPC 每帧更新 `0x005ABE96` 调用） |
| +0x48 | `0x005F7951` | 到期：`+0x34 < 0`。调用方没在普通代码里找到 [推断：加壳区] |
| +0x40 | `0x005F78F8` | 返回 0：变身不影响 `0x005ACF9E`，Boss 照样捡道具 |
| +0x50 | `0x00611C67` | 返回 **8**：移动档 8（读取方是加壳的 `0x0087E6CA`，标推断；服务端目录 `SpeedRate 8` 与此一致） |
| +0x54 | `0x00611C6B` | 可用泡数 = **8 − 已放数**（`0x005AD065`） |
| +0x58 | `0x005F7979` | 威力 = 原属性对象的 `P->vtbl+0x20`，**不变** |
| +0x5c | `0x00611C81` | 方向重映射：RoleID 是 24、28 或大于 28（所有命名 Boss）时**原样返回**；其他角色 0↔2、1↔3，即方向键反向 |
| +0x18 | `0x005F78BF` | 站立、朝向 3、3000 ms 免伤。推断是到期卸下时调用 |
| +0x2c | `0x005F798D` | 空函数（`0x005ADF5A` 换下旧变身时调用） |

服务端 `sceneelement.NativeTransformation(110)` = `{AvatarRoleID 42, 30 s, SpeedRate 8, BombCapacity 8, ReverseDirection}` 与此一致。只是"反向"对 Boss 不生效。

### 4.3 变身中的 Boss
- `0x005ADF5A(t)`：先删掉旧变身，再把 `N+0x404` 设为 t。非本地控制的一端还会把朝向设为 3，并定位 avatar；本地控制的一端（仲裁方）只定位。
- AI：每次决策 `0x005B0BAF` 都把全局引信 `G+0xf88` 设为 **2500 ms**（只在仲裁方）。通用技能 3 在 `N+0x404 != 0` 时跳过，等变身消失后再按 30 s 冷却重新发放。放泡的数量用变身的 `+0x54`。
- **被炸**（`0x00601FEC`，0x10F4 的 IsAvatar = `N+0x404 != 0`）：只调用 `0x005ADF5A(0)` 解除变身，**不扣 HP**，也不掉落 0x116B。`0x005ADF5A(0)` 在本地控制的一端（仲裁方，Boss 在 NPC 列表里）另外给 `+0x318` 组件 `0x005B5202(3000)`（3 s 免伤，带 `flash2.eff`）。其他客户端解除变身时没有闪光。
- 能否受伤：`0x005AD175` 在变身时看变身对象自己的免伤（`vtbl+0x14`），所以装上变身后的 3 s 里打不动 Boss。
- 30 s 后自然到期（推断走 `+0x48` → `+0x18`），回到原模型。

### 4.4 移植要点
```
onSkill3(boss):                         // 仲裁方
  send 0xFAD{boss.id, time+1000000, 110, x, y} 给所有端，并本地执行：
  boss.transform = Demon{remain: 30000, invulnUntil: now+3000}
每帧：remain -= dt；remain < 0 → 卸下，Boss 3 s 免伤
G.fuse = (now > 60000 && HP >= 3) || boss.transform ? 2500 : 2990
0x10F4 命中变身 Boss → 卸下变身（不扣血、不掉落），仲裁方给 3 s 免伤
放泡上限 8；移动档 8；Boss 方向不反向；渲染 body14201
```

## 5. 未证实 / 待查

1. 禁泡期间 `+0x424` 打开的 `+0x428` 组件由谁创建、画什么，普通代码里找不到，可能是加壳区创建或根本不存在。
2. `0x005AE618`（石化倒计时恢复模式）和变身到期检查（`vtbl+0x48`）都只能从加壳区调用，时长和效果按代码推出，没有黑盒验证。
3. 石化中被炸成困泡后，倒计时结束会不会让玩家走出泡泡（§3.3），需要录像核对。
4. 技能 6 的第二波选格是否避开第一波，取决于本地分发是否同步（§2.3）。
5. 技能 6 的泡 `+0x24` 设为施法时间。泡飞到目标格之前就到引信时间（最远 14 格 × 100 ms = 1.4 s，比 2.5～3 s 的引信短）时，按踢炸弹移植的做法应该不会发生，但飞行中能否被引爆、能否被踢没有核对。
6. `S+0x4b34`/`S+0x4b38` 的确切含义（推断：本机玩家 / 当前操控或观战的角色）。
7. Boss 死亡时 `0x005B9390` 给全部角色禁泡 +1，同时可能改写 `M+0x3838`（`规则时间 − M+0x3970 > 10000` 时设为 `规则时间 − 10000`）。之后谁解禁、这是不是"Boss 战结束"的流程，没有追。
8. 海盗只在"够不到任何玩家、附近也没有道具"时才检查技能（AIType 3/4 的结构）。录像里技能是否比这更频繁，没有对照。如果更频繁，说明原服务端给的不是 AIType 3，或者另有调用路径。
9. 大副 HP 10 时实际上不放任何技能，直到被打到 HP 7。如果目录要让大副一开场就放技能，需要降低 HP（这只是服务端配置，不是原版数据）。
