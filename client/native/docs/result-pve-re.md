## 原版读取与计算

探针仍执行 `0x00602BAB/0x00881E00` 完整字段转换。本轮为其补上真实资源依赖：用QQTSection.dll `0x1002BCDF` 读取、解密、解压 `config/pvedata.dat`，将原版读取器实际输出接给Client.exe的RoomModule虚表+64。Client.exe `0x00602F9B` 自己解析XML并计算百分比，没有把宿主的计算结果注入原版。

资料中的竞技积分为+0x34，勇气积分为 **+0x4F**。GAME_INFO是47字节紧凑布局，不能按本机C/C++对齐猜成+0x50；写错一个字节会把小整数变成左移8位后的值。宿主直接使用已解码的 `GameInfo.extended_points`，不再依赖二进制偏移。

原包有31项勇气阈值，开头为0、573、1289、2447，最高428326799。规则为：找到 `low <= points < high`，返回float32的 `(points-low)*100/(high-low)`。找不到下一级区间时返回0，最高档亦如此。它与竞技积分的包含上界规则不同：勇气573的百分比为0，竞技1000的百分比则为100。

| 0 | 0 → 17.4520072937 |

| 428326799 | 0 → 0 |

起点100、GAME_OVER Point=50、Score为空时，目标仍是17.4520072937；Point不增长勇气条。Score=[0,0,30,100]则四项全计入，增长130。场景+51A4为0/1/2的探险结果均走这条计算，不套用普通竞技模式1的0/0分支。

结果标题和行等级仍沿原版显示结构的竞技等级投影：竞技资料积分加Score总和，与普通结果相同。本轮移除了旧宿主探险专用的“竞技积分+Point”例外。经验条改用pvedata，位置使用探险base=130，即(268,205)，双层裁切和只向较大目标增长的时钟沿用已验证的原生结果控制器。
