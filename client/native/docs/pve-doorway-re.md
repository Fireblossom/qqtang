# 双人同时进门的重复换关请求

2026-11-04，接续 `pve-motion-re.md` 的真实双端验收。

## 触发与修正

两个本机玩家都能独立检测已清怪关卡的门，并发送0x1178。实局中客人先进入1602，服务端将同一场比赛的两端投影到新关；约1ms后房主从旧场景发出的“进入1602”到达。原处理只按新的CurrentMapID1602验证，因它现在期望1603而记下 `invalid next-map request ... next_map=1602 current_map=1602`。两端实际上均已收到1602，属于重复完成请求。

服务端现在为比赛保存最近一次成功的地图边（previous/current）。验证发送者身份、当前阶段参与者和原路线后，若明确目的地仍指向刚完成的地图边，只返回本次请求的ACK，并记录 `qqt_adventure_next_map_duplicate_<map>`。不重新生成关卡通知、种子、道具表或结算，也不改变本关清怪进度。

玩家会话已经应用新关投影或仍在排队应用，都使用同一比赛的地图边判断。保留原版目录跳号兼容，例如1646请求1647而实际进入1648；新请求要进入1603时继续走当前关卡清怪校验。目标0没有旧关标识，仍使用普通本关验证；这次没有把含糊目标一律当重复成功。

地图边只在成功AdvanceStageWithRule时更新，失败不改变。新比赛没有previous，前两关以前的旧目标也不会被当成最近一次重复。房间TCP权威处理仍由既有room actor串行化。

## 回归与本地部署

新回归使用临时生成的真实目录格式，不依赖缺失的 `runtime/client-patched`，不会因发行资源缺席而跳过。覆盖：两个参与者、会话投影前/后、普通/跳号地图边、身份不符、非参与者、路线错误、无关目标、目标0、当前关未清怪、新比赛无历史，以及正常清怪后继续下一关。重复请求逐项断言没有follow-up、结算或状态/种子/统计变化。
