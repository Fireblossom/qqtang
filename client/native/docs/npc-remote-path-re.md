# NPC远端保持阶段的拐角、终点与逐帧精度

2026-11-04，接续 `npc-remote-re.md` / `pve-remote-re.md`。已移除每帧从报文起点按总路程重算三段的近似，规则1/2/8与探险共用的接收端现在保留原版保持阶段的位置小数和拐角阶段。

## 原版行为

真实 `0x005D1348` 消费一条解码记录，将控制器+34重置为-1。没有下一条待消费记录时，`0x005D13C2` 读取Actor+3B0的玩家表标量，按PC24精度计算 `scalar * dt * 0.04`，调用四方向函数 `0x005D1464/15AF/16FA/184B`。

- 阶段-1接近角点；主轴位置先截断成整数，距离角点小于2时对齐角点并立即开始垂直修正。还没进入这个整数容差时，移动后进入角点前1px范围会吸附角点，但当帧不继续垂直走。
- 阶段0垂直修正，调用 `0x005D199F/1A00`；是否到达由移动后的截断整数判断，因此不能简单用浮点距离取min。
- 修正结束变为阶段1，当帧不再沿主轴前进；下一帧由 `0x005D1A61` 沿主轴推进并钳制终点。
- 原版不把越过角点的剩余路程分给后续段。阶段0主轴失配、阶段1退回角点前方、无角点但保留0/1等情况也有单独的对齐与阶段重置分支。
- 无角点时直接沿方向走到终点，不额外把垂直坐标移向End的另一坐标；walk标志不会因为到达终点而清零。

例如2档向右，起点(318,260)、Corner(320,260)、End(380,280)，每帧20ms：首帧吸附到(320,260)，阶段0；第二帧才到(320,261.44000244140625)。若起点已经是(320,260)，首帧就进入垂直修正。连续累加的float32结果也与每帧从总时长重算不同。
