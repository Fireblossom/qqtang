# 控件背景状态帧与动画时钟

2026-11-04。宿主原先用渲染器全局时间取模，把 `framespeed` 当倍率；状态帧顺序则由图片外观推断。现改为逐控件保存状态、逻辑帧、帧时钟和循环时钟，按实际gameUI执行结果推进。

## 原版证据

- `0x1002A16B` 根据E4标志选择按下0、悬停1、正常2、禁用3。按下不要求同时悬停，禁用优先。属性加载器 `0x1002B42F` 把声明的四对起止帧拆成四个起点、四个终点；Python2属性解析未整体模拟。
- 构造器 `0x100267B8` / `0x10003F1D` / `0x100048AC` 后实际运行虚表+B0生成默认方案：WIDGET全为0；BUTTON依次0、1、2、3；CHECK未选全0、已选全1。没有显式方案的普通控件不会自动播放整张多帧图。
- `framespeed` 默认0.15秒，`loopspeed` 默认0。每次更新以float32累计秒数，达到帧间隔只递增一帧，帧时钟清零，不保留余量。递增到起点+1时，循环时钟不足loopspeed便退回起点；达到则清循环时钟。越过方案终点才回起点。
- 状态变化重置逻辑帧至新起点、循环时钟至loopspeed，保留帧时钟。CHECK更新 `0x10004982` 先按选中位选择有效方案行，再执行共用更新；仅换行不会强制重启同状态时钟。树更新 `0x1002A0E9` 无可见性过滤。
- 背景绘制 `0x100297F3` 实际调用图像包装 `0x10013238`：负帧不画；超过资源帧数时先画资源最后一帧，返回溢出标志，再把逻辑帧重置至当前方案起点。bkImgFlag位8在此时设置背景隐藏标志，后续不画。透明度量化为0时整个绘制跳过，不提前处理溢出。
- 换图 `0x10028871` 对相同路径直接返回；清空或更换路径重置逻辑帧与背景隐藏标志，保留两个时钟。探针实际覆盖相同路径及空字符串；图像名称查询、释放出口受控。

## 校验与实测

```sh
.venv/bin/python tools/probe_ui_animation.py /path/to/client-patched
```
