# 新手任务（新手教程）

2026-11-17，静态逆向 `Client.exe`、`QQTSection.dll`；2026-11-19 补充关卡部分并实现。代码在 `qqtclient/battle/tutorial.py`（外层流程）、`qqtclient/battle/tutorial_stage.py`（关卡画面）、`cmd/qqt-battle-sidecar/tutorial*.go`（Task.txt 控制器）和 `internal/game/battleengine/tutorial.go`，入口接在 `__main__.py`。

## 状态

都在游戏管理对象 `0x00806A78`（`0x005A1DE1` 返回）上：

| 偏移 | 含义 | 读写 |
| --- | --- | --- |
| `+0x56EEF` | 新手任务对局 | `0x00490B70` 置位；`0x005A4181`、`0x005A26C1` 清除 |
| `+0x56EED` | 首次新手任务 | `0x005A4174`；`sc_firstBeginTutorial` 置 1，结束时执行 `NewPlayerPractice()` 后清 0 |
| `+0x56EFF` | 正在播放教学录像 | `0x00490BA0(1)` 置位并把计数清 0；录像链结束时清 0 |
| `+0x56F00` | 已开始播放的录像数 | `0x00490BE0` 加 1，`0x00490C20` 读 |
| `+0x56F04` | 自由练习 | `0x00490C80` |
| `+0x56EF4` | 任务控制器（见下） | GAME_BEGIN 处理 `0x005A2089` 创建 |
| `+0x56EE0` | 模式：1 普通对局，3 录像回放 | |

## 开始

- 大厅“新手练习” → `uiTaskSelDlg` → “新手任务”：脚本先 `DisableEnterRoom()`，再调用 `sc_beginTutorial()`。
- `sc_beginTutorial`（`0x0048E690`）：置 `+0x56EEF`；若已有任务控制器且计数非 0，计数清 0；然后取 Section 服务（GUID `0x0079A908`）虚表 `+0x1B0`，即 QQTSection `0x1001C5A7`。
- QQTSection `0x1001C5A7` 与自由练习的 `0x1001C6F2` 几乎相同：清零 0x5AE 字节的 GAME_BEGIN 结构，人数 1、地图 `0x5DD`（1501），只放本机一名玩家，交给对局监听者 `+8`，也就是本地开局。两者唯一的差别是地图号和一个本来就为 0 的字节（`+0x33D`）。
  - 本机的 Role 是 8（`+0x5B3`，函数开头写入 `-0xBD4A`），也就是海王子（说话头像 misc368）；结构清零，所以没有道具表（实测，2026-11-19）。
- `sc_firstBeginTutorial`（`0x0048E650`）：`+0x56EED = 1`，再执行脚本 `sc_beginTutorial()`。它不是脚本调用的，而是 QQTSection 进分区的回包处理 `0x1001B2EA` 在执行 `DealInitialize()` 之后调用的（`0x1001BCD1`），条件是：
  - Section `+0xC768`（回包里的 SectionMode 字节，`0x1001B2EA` 用 `0x10029E4F` 写入）不等于 1（`0x10029E3F`）；
  - 回包 GameInfo 的胜、负、平三项之和小于 1（`0x1001BCBC`）。
  服务端 `internal/protocol/game/profile.go` 的 `TutorialCompleted` 就是按这个条件给一次平局来跳过首次教程。
- `beginTutorial1`（`0x0048E7F0`）只调用 `+0x1B0` 开局、不置 `+0x56EEF`。三个程序和脚本里都没有调用它。
- 宿主：`sc_beginTutorial`、`sc_firstBeginTutorial`、`beginTutorial1` 都已接上；进分区后在 `session.on_entered` 里按同样条件调用首次教程。

## 结束（`0x005A4181`）

新手任务和自由练习的对局结束（`0x005A3E98` 结果显示倒计时到 0）、或玩家点“离开”（`0x005A26C1` 先回 `selRoom`，再 `0x005A2C6D` → `0x005A4181`），都走这个函数：

1. 按地图把关卡号记成 0～3（1501～1504，其他为 4），连同场景时钟交给 `+0x7D0` 对象的虚表 `+0x38`：教程填（关卡号, 1），剩余任务少于 5 条时另填 1000；自由练习填（0, 2）。推断是统计上报，宿主不做。
2. 清 `+0x56EEF`，销毁场景和任务控制器，清掉等级图标。
3. 如果不在播放教学录像（`+0x56EFF` 为 0）：
   - 自由练习：只回 `selRoom`（`0x005A3F12(1)`）。`0x005A439E` 判断 `+0x56F04` 非 0 后直接跳到 `0x005A4438`。
   - 新手任务：回 `selRoom`；首次（`+0x56EED`）则执行 `NewPlayerPractice()`（重新打开练习选择框，并显示 `UI.newPlayerDirectionDlg` 气泡“您现在可以重复新手任务，也可以选择进行自由练习……”），然后清 `+0x56EED`；
     否则通过服务 `0x0079DE58` 虚表 `+0x10`（`0x0052CB80` → `0x0048B130`）弹出“您是否需要观看高手玩家录像？”（`0x007F2378`），句柄 `0x2000008`，之后执行 `ui_msgBox(0)`，按钮是“确定/取消”。
4. 如果正在播放教学录像且 0 < 计数 < 3：执行 `SC_PlayTutorialRecord()`。
5. 清 `+0x56F04`。

所以中途离开新手任务，和打完一样会弹出录像询问（或首次时的练习框）。

宿主以前把自由练习做成“打完后重新弹练习框”，与原版不符，已改为只回大厅；`keylayout-re.md` 的记录一并改正。（2026-11-18 起自由练习按钮打开宿主新增的离线练习房间，见 `offline-ai-re.md`；`QQT_DIRECT_FREE_PRACTICE=1` 时仍按上面的原版流程直接开局。）

## 高手录像

- 询问框按“确定”：脚本 `OnMsgBoxOk` 对非负句柄调用原生 `OnMsgBoxResult(h, 1)`（`0x0048B410`）。它按 `h >> 24` 分发，2 是 Section 服务虚表 `+0x164`，即 QQTSection `0x10023458`；`case 8` 在确定时执行脚本 `SC_PlayTutorialRecord()`（`0x100617C4`）。取消什么也不做。
- `SC_PlayTutorialRecord`（`0x0048C960`）：
  - 计数为 0：`+0x56EFF = 1`、计数清 0，计数加 1，`PlayRecord("tutorial1.qbv")`（`0x005A36CE`）；
  - 计数为 1、2：计数加 1，播放 `tutorial2.qbv`、`tutorial3.qbv`；
  - 其他什么也不做。
- 每段录像结束或被“离开”（回放模式 3 的 `0x005A2C6D`）：`+0x56EFF` 置位且 0 < 计数 < 3 时，先 `ui_NotifyShowLevelIcon(0, i, 0)`（i = 0～7），再执行 `SC_PlayTutorialRecord()` 播下一段；否则清 `+0x56EFF` 和计数，回 `selRoom`。
- 三段录像的内容（`replay-re.md`）：`Tutorial1.qbv` 地图 311 普通对战，`Tutorial2.qbv` 抢包子 806，`Tutorial3.qbv` 踢炸弹 704，都由 QQ 7354982 录制。它们是“高手玩家录像”示范，不是关卡本身。
- 宿主：询问框用 `show_msgbox` + `ui_msgBox(0)` 弹出；原生 `OnMsgBoxResult` 包了一层，只截下 `0x2000008`，其他句柄照旧；录像用已有的 `ReplayBattle` 播放，结束回调按上面的规则接下一段。文件名原版写小写 `tutorial1.qbv`，发布包里是 `Tutorial1.qbv`，宿主不区分大小写查找。

## 关卡：Task.txt 任务控制器

2026-11-19 补充逆向并实现。标注：**实测**＝读了伪 C 或机器码、或量过数据文件；**推断**＝合理但没有直接证据；**[宿主]**＝原版查不到、由宿主决定。

### 实现

- 侧车新增“新手任务模式”（`cmd/qqt-battle-sidecar/tutorial.go`、`tutorial_task.go`），初始化命令是 `{"cmd":"init","tutorial":{...}}`。
  - 原版的新手任务本来就是本地单机对局，所以这里只建一个引擎。离线对战那套“每个座位一个客户端、本地裁判”的结构在这里用不上，复用的是其中的地图目录、机器人和状态输出。
  - 控制器（读 Task.txt、执行动作、例程、计时、死亡和吃道具回调）在侧车里，和引擎同一个时钟，每个 20 ms 的 tick 跑一帧。
  - 每次回复是引擎状态加一个 `tutorial` 字段：提示序号和头像、目标箭头、酷比、剧情卷轴进度、任务卡、隐藏界面层、输入是否放开、侧边栏、结果字节。切换地图时附带新的 `begin`。
- 引擎（`internal/game/battleengine/tutorial.go`）新增的接口只有侧车的新手任务模式调用，规则开关 `Rules.NativeTutorial` 默认关闭：
  - `ConfigFromTutorialMap`：允许只有一名玩家开局；
  - `AddActor`：中途加角色；
  - `TeleportActor`：瞬移；
  - `TrapActor`：困泡，并可延长困泡时间；
  - `SetFlameImmune`：免疫泡泡。
- 地图目录 `mapdata.Catalog.TutorialMap` 读入 `practice` 家族的 1501～1504。这几张图仍不进竞技地图表，不能被选。
- 宿主（`qqtclient/battle/tutorial_stage.py`）：
  - 用现有的 `BattleScene` 画对战；
  - 提示调用 uiGame 自己的 `NotifyAddHint` 和 `NotifyRemoveHint`；
  - 自己画说话头像、箭头、酷比、侧边栏、卷轴和任务卡；
  - 新地图开局时重建场景；
  - 收到结果后显示胜利或失败，再走原有的结束流程。
- 侧车命令里的 `any_key` 表示“上一步以来有键按下”；提示的“空格”是放泡键（见下）。
- 测试和截图用的 `"autoplay": true` 或环境变量 `QQT_TUTORIAL_AUTOPLAY=1`：由一个驱动程序代替键盘（`tutorial_autoplay.go`），只在放开输入的阶段操作。它的行为是走向箭头、炸开挡路的海葵、吃道具、守住 1504 左上角、311 交给离线机器人。正常游戏不会用到它。

### 控制器（实测）

- 记录：Task.txt 按“整数＋一个分隔符”连读，每 10 个整数一条（`0x005C6044`；第 10 个整数后不读分隔符，所以换行无关）。
  - 每条 32 字节：f0～f6 是 7 个 short，f7、f8、f9 是 3 个 int，最后是状态（1 新，2 执行中，3 完成）。
  - 坐标对是（列, 行）：瞬移 `0x005AD322` 收到的是 (f5×40+20, f6×40+20) = (x, y)。
  - 文件实际有 71 条（`TestTutorialParsesTaskFile`）。
- 本机 id 加两次：加载时 f0 加一次，执行时再加 `+0x68`（本机 id）一次。
  - 生成和查找角色时加法一致，吃道具插入的提示记录写的是“本机 id＋1”，再加一次后也对得上。所以只要本机 id 一致就不出错。
  - 宿主只加一次，结果相同。
- 每帧（`0x005C5F3A`）：
  - 状态 3 且表里不止一条：弹出队首，下一条立即进入状态 2（`0x005C6187`）；
  - 状态 1：进入状态 2（`0x005C61DE`）；
  - 状态 2：执行（`0x005C6221`）；
  - 表空：直接 `0x005A4181`（数据里走不到）。
- 例程模式（`+0xAD = 1`）：不再执行任务表，只对每个角色执行它当前的例程步骤（`0x005C7185`）。
- 换图（动作 10）：`gm` 虚表 `+0x2C` 用同一份 GAME_BEGIN 在新地图重新开局。控制器的 `+8`（`0x005C5F8A`）在任务表非空时只重新绑定场景和本机，并退出例程模式。新场景里的酷比、箭头、侧边栏、吃到的道具都重新开始。

### 动作（实测，跳转表 `0x5C70D6`）

| 动作 | 输入 | 作用 |
| --- | --- | --- |
| 1 | 锁 | 等 f7 毫秒 |
| 2 | 锁（强制行走） | 本机走向 (f5,f6)；中心进入该格后瞬移到格心并停下。原版写方向 0（推断向右），两处数据都向右，宿主改为按路径走 |
| 3、29 | 锁 | 本机说提示 f9，满 5000 ms 或按放泡键结束。3 用本机头像，29 用酷比头像（见“画面”） |
| 30 | 锁 | 酷比说提示 f9，只能等满 5000 ms；然后在 (f5,f6) 显示目标箭头（`0x005C6F82` 以格心为位置，`0x005D21E9(1)` 显示） |
| 5 | 锁 | 本机瞬移到 (f5,f6) |
| 6 | 锁 | 在 (f5,f6) 生成角色 f0。f9 为 0：Role 3、本队；否则 Role 0x19、队伍＋1。泡 2、威力 2、速度档 (f7==0)+1。AI 类型在 1501～1504 为 1，其他地图为 2 |
| 7 | 锁 | 角色 f0 寻路走向 (f5,f6)（角色虚表 `+0x74`），所在格等于目标时完成 |
| 8 | 锁 | 角色 f0 说话，满 5000 ms 或按放泡键结束 |
| 10 | 锁 | 换到地图 f9 |
| 11 | 锁 | 角色 f0 在自己脚下放泡 |
| 12 | 锁 | 角色 f0 说话，只能等满 5000 ms；然后显示箭头 |
| 13 | **放开** | 等本机进入 (f5,f6)：停下、隐藏箭头 |
| 15 | 锁 | 在 (f5,f6) 生成 Role 3 本队角色（速度 2）并困住，困泡时间 `+0x3C4` 加 240000 |
| 16 | 锁 | 再困一次并再加 240000 |
| 25 | 锁 | 读后面 f9 组例程，进入例程模式 |
| 27 | 锁 | 剧情卷轴：固定 10000 ms（Task.txt 写的 12000 没有用到），或按任意键结束；期间 `gm+0x56EFD = 0`，场景 `+0x4E0F = 1` |
| 28 | 锁 | 任务卡：5000 ms 或任意键 |
| 32 | **放开** | 在 (f3,f4) 格心放酷比图（`0x005C6EC1`），立即完成 |
| 33 | **放开** | 每帧隐藏箭头；吃齐 9 种（`+0xB0 == 9`）后完成 |

- 输入锁：`+0xAC` 不是 4 时，放泡 `0x00610BA0` 和移动 `0x006112AF` 都不处理。例程每一步都把 `+0xAC` 设成 4，所以例程模式下输入放开。
- 提示的“空格”：`0x005A4BF7` 读的是 `gm+0x11`，也就是放泡判断用的同一个标志，所以实际是玩家设定的放泡键。宿主取本步第一个 tick 的放泡脉冲。
- “任意键”：`0x005A542E` 扫 256 个按键，读到就清掉。宿主用上一步以来有没有按键。
- 未知动作在原版里永远不会完成；宿主让它直接完成，并写日志。

### 例程（实测，`0x005C7185`、`0x005AFB86`、`0x005AFB1A`）

- 动作 25：其后每组先是组头（f0 是角色，f9 是步数），再跟步骤。这些记录连同 25 本身都从任务表删掉。
- 每个角色有自己的步骤表（角色 `+0x430`）和当前步（`+0x444`）：
  - 一步完成后进入下一步；最后一步完成后回到第一步。
  - 每一步开始时记下时间 `+0x43C`。
- 步骤动作：
  - 7：走到 (f5,f6)。完成后如果目标是 (列 0, 行 1) 或 (列 0, 行 13)，就分发 0xFBB 判负。（行 13 超出 13 行的地图，走不到，原版 bug。）
  - 0xB：放泡。
  - 0x18：等 f7 毫秒。
  - 0x1A：瞬移到 (f5,f6)。
  - 0x1F：退出例程模式，数据里没有用到。
- 复活（0x17）：死亡回调把一条“0x17、10000 ms”记录放进角色的 `+0x444`。等满 10 秒后，用 `0x005C5EB5` 取角色当前的例程步骤，分发 0xFBA（处理函数 `0x00603754`）把角色复活到该步的 (f3,f4)，再从第一步重新开始。
  - 数据里每一步的 (f3,f4) 都是这一段的起点，所以敌人会在 (13,1)、(13,11) 复活。
  - 复活时 `+0x3B7` 等于 4 的分支会取到 0x17 记录本身，(f3,f4) 是 (0,0)。没有查清死亡后 `+0x3B7` 的值；宿主一律用当前步骤（推断）。
  - 例程只在例程模式下执行，所以 1504 演示阶段被打死的敌人 2 要等例程开始后才复活（测试里在 19.6 s 死亡，例程开始后复活）。

### 死亡、计时、吃道具（实测）

- 死亡 `0x00606606`（0xFA7），在新手任务中：
  - 死者与本机同队：发 0xFBB，结果字节 0（负）。包括本机自己和小倩。
  - 死者是对手，且地图不在 1501～1504（即 311）：发 0xFBB，结果字节 2（胜）。
  - 在 1501～1504 上：给死者挂上 0x17 复活记录。
- 结果字节就是 GAME_OVER 的结果码：0 负，1 平，2 胜（`internal/protocol/game/enums.go`）。
- 0xFBB 让场景进入状态 2（`0x005C874F`），即对局结束、显示结果、倒计时后 `0x005A4181`。
  - 规则 9 的结束回调 `0x006097AF` 也直接调 `0x005A4181`。
  - 宿主显示“胜利！/失败”横幅 12 秒（或按键），然后走原有结束流程。横幅的样子和时长是推断，与自由练习相同。
- 计时 `0x0060D6E5`，从开局算起：
  - 1501～1503：满 240 s，先调控制器 `+0x24`，再发 0xFBB（结果 0）；
  - 1504：满 70 s，调控制器 `+0x2C`（`0x005C74EC`：退出例程模式，从任务表队首重新开始），也就是继续执行“换到 311”；
  - 其他地图（311）：满 240 s 发 0xFBB，结果 2（判胜）。
  - 规则 9 的对局时间是 240000（`0x006097D3`），界面计时器从 4:00 倒数。
- 本机在 1501～1503 不会被泡泡困住：每帧的本机炸伤检测 `0x00607899` 在规则 9 且地图在 1501～1503 时跳过。宿主用 `SetFlameImmune` 实现。其他角色照常会被炸，小倩被困 6 s 后死亡就会判负。
- 吃道具 `0x00604DB0`：
  - 规则 9 且地图 1503 时调 `0x0060528C`。
  - 已吃种类少于 9 时，新种类按 `0x00605386` 映射提示（不在表里的是 1，表示不算）：
    - 1→16，2→17，3→18，4→21，23→22，24→19，25→20，61→23，81～84→24。
  - 新种类会在任务表最前面插入一条“角色 本机+1、动作 8、提示 N、5000 ms”并立即开始（`0x005C7492`），`+0xB0` 加 1（只在 1503，`0x005C751A`）。
  - 已满 9 种时再吃，就把当前记录标为完成。
- 侧边栏的道具图（`0x005EE60D`）与地图无关，按道具设帧：
  - 23→8，1→5，2→7，3→9，4→10，21→3，24→1，25→4，27→2，61→6，81～84→11，其他→0。

### 宿主的决定和偏差

- **1503 的道具 [宿主]**：
  - QQTSection 的本地 GAME_BEGIN 把整个结构清零，没有道具表；1503 的地图文件也没有墙内道具表。这一关却要求吃齐 0x00605386 认识的 9 种道具，原版道具从哪来没查到。
  - 宿主把 1、2、3 各 4 个，4、23、24、25、61、81 各 2 个，共 24 个，用道具种子撒进 92 个可炸格。
  - 自动驾驶在 4 个种子下都能在 240 s 内吃齐。真人时间够不够没有验证。
- **311 的道具 [宿主]**：用地图自己的墙内道具表，按服务端的方法掷数。原版本地开局同样没有道具表。
- **AI 类型 2 [宿主]**：311 的敌人由离线模式的机器人（`autoplay.go`，离线改进版）操作。原版 AI 类型 2 的实现没有移植。
- **寻路 [推断]**：脚本角色（动作 7、例程 7）走最短路径，只走空地，绕开泡泡；找不到路就原地等。原版角色虚表 `+0x74` 的寻路没有移植。
- **速度档 1、2**：按引擎的档位表换算成 40、72 像素/秒（实测换算表），敌人比本机（Role 8，档 5）慢。
- **困泡时间**：普通困泡 6000 ms 后死亡，沿用联网模式的本机困泡时间。动作 15、16 再加两次 240000。
- **本机 id**：宿主本机 id 是 1，角色 id = 1 + f0，加法只做一次（原版 bug 不影响结果）。
- **结果画面**：只显示横幅，没有成绩表。原版是否显示成绩表没查。
- **头像、箭头、酷比、卷轴速度、任务卡位置、侧边栏叠放顺序**：见“画面”中标注的**推断**。
- **0xFBB 判负的第 13 行检查** 保持原样（走不到）。动作 0x15（每帧重发 0xFBB）、0x16（越界判断恒假）的原版 bug 数据里用不到，宿主没有实现这两个动作。
- **侧车之外的原版逻辑没有接**：新手任务的统计上报（`0x005A4181` 第 1 步）。
