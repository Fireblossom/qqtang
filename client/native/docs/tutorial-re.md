# 新手任务（新手教程）

2026-11-17，静态逆向 `Client.exe`、`QQTSection.dll`。代码在 `qqtclient/battle/tutorial.py`，入口接在 `__main__.py`。

## 状态

都在游戏管理对象 `0x00806A78`（`0x005A1DE1` 返回）上：

| 偏移 | 含义 | 读写 |
| --- | --- | --- |
| `+0x56EEF` | 新手任务对局 | `0x00490B70` 置位；`0x005A4181`、`0x005A26C1` 清除 |
| `+0x56EED` | 首次新手任务 | `0x005A4174`；`sc_firstBeginTutorial` 置 1，结束时执行 `NewPlayerPractice()` 后清 0 |
| `+0x56EFF` | 正在播放教学录像 | `0x00490BA0(1)` 置位并把计数清 0；录像链结束时清 0 |
| `+0x56F00` | 已开始播放的录像数 | `0x00490BE0` 加 1，`0x00490C20` 读 |
| `+0x56F04` | 自由练习 | `0x00490C80` |
| `+0x56EF4` | 任务控制器（见下） | GAME_BEGIN 处理 `0x005A2089` 创建 |
| `+0x56EE0` | 模式：1 普通对局，3 录像回放 | |

## 开始

- 大厅“新手练习” → `uiTaskSelDlg` → “新手任务”：脚本先 `DisableEnterRoom()`，再调用 `sc_beginTutorial()`。
- `sc_beginTutorial`（`0x0048E690`）：置 `+0x56EEF`；若已有任务控制器且计数非 0，计数清 0；然后取 Section 服务（GUID `0x0079A908`）虚表 `+0x1B0`，即 QQTSection `0x1001C5A7`。
- QQTSection `0x1001C5A7` 与自由练习的 `0x1001C6F2` 几乎相同：清零 0x5AE 字节的 GAME_BEGIN 结构，人数 1、地图 `0x5DD`（1501），只放本机一名玩家，交给对局监听者 `+8`，也就是本地开局。两者唯一的差别是地图号和一个本来就为 0 的字节（`+0x33D`）。
- `sc_firstBeginTutorial`（`0x0048E650`）：`+0x56EED = 1`，再执行脚本 `sc_beginTutorial()`。它不是脚本调用的，而是 QQTSection 进分区的回包处理 `0x1001B2EA` 在执行 `DealInitialize()` 之后调用的（`0x1001BCD1`），条件是：
  - Section `+0xC768`（回包里的 SectionMode 字节，`0x1001B2EA` 用 `0x10029E4F` 写入）不等于 1（`0x10029E3F`）；
  - 回包 GameInfo 的胜、负、平三项之和小于 1（`0x1001BCBC`）。
  服务端 `internal/protocol/game/profile.go` 的 `TutorialCompleted` 就是按这个条件给一次平局来跳过首次教程。
- `beginTutorial1`（`0x0048E7F0`）只调用 `+0x1B0` 开局、不置 `+0x56EEF`。三个程序和脚本里都没有调用它。
- 宿主：`sc_beginTutorial`、`sc_firstBeginTutorial`、`beginTutorial1` 都已接上；进分区后在 `session.on_entered` 里按同样条件调用首次教程。

## 结束（`0x005A4181`）

新手任务和自由练习的对局结束（`0x005A3E98` 结果显示倒计时到 0）、或玩家点“离开”（`0x005A26C1` 先回 `selRoom`，再 `0x005A2C6D` → `0x005A4181`），都走这个函数：

1. 按地图把关卡号记成 0～3（1501～1504，其他为 4），连同场景时钟交给 `+0x7D0` 对象的虚表 `+0x38`：教程填（关卡号, 1），剩余任务少于 5 条时另填 1000；自由练习填（0, 2）。推断是统计上报，宿主不做。
2. 清 `+0x56EEF`，销毁场景和任务控制器，清掉等级图标。
3. 如果不在播放教学录像（`+0x56EFF` 为 0）：
   - 自由练习：只回 `selRoom`（`0x005A3F12(1)`）。`0x005A439E` 判断 `+0x56F04` 非 0 后直接跳到 `0x005A4438`。
   - 新手任务：回 `selRoom`；首次（`+0x56EED`）则执行 `NewPlayerPractice()`（重新打开练习选择框，并显示 `UI.newPlayerDirectionDlg` 气泡“您现在可以重复新手任务，也可以选择进行自由练习……”），然后清 `+0x56EED`；
     否则通过服务 `0x0079DE58` 虚表 `+0x10`（`0x0052CB80` → `0x0048B130`）弹出“您是否需要观看高手玩家录像？”（`0x007F2378`），句柄 `0x2000008`，之后执行 `ui_msgBox(0)`，按钮是“确定/取消”。
4. 如果正在播放教学录像且 0 < 计数 < 3：执行 `SC_PlayTutorialRecord()`。
5. 清 `+0x56F04`。

所以中途离开新手任务，和打完一样会弹出录像询问（或首次时的练习框）。

宿主以前把自由练习做成“打完后重新弹练习框”，与原版不符，已改为只回大厅；`keylayout-re.md` 的记录一并改正。

## 高手录像

- 询问框按“确定”：脚本 `OnMsgBoxOk` 对非负句柄调用原生 `OnMsgBoxResult(h, 1)`（`0x0048B410`）。它按 `h >> 24` 分发，2 是 Section 服务虚表 `+0x164`，即 QQTSection `0x10023458`；`case 8` 在确定时执行脚本 `SC_PlayTutorialRecord()`（`0x100617C4`）。取消什么也不做。
- `SC_PlayTutorialRecord`（`0x0048C960`）：
  - 计数为 0：`+0x56EFF = 1`、计数清 0，计数加 1，`PlayRecord("tutorial1.qbv")`（`0x005A36CE`）；
  - 计数为 1、2：计数加 1，播放 `tutorial2.qbv`、`tutorial3.qbv`；
  - 其他什么也不做。
- 每段录像结束或被“离开”（回放模式 3 的 `0x005A2C6D`）：`+0x56EFF` 置位且 0 < 计数 < 3 时，先 `ui_NotifyShowLevelIcon(0, i, 0)`（i = 0～7），再执行 `SC_PlayTutorialRecord()` 播下一段；否则清 `+0x56EFF` 和计数，回 `selRoom`。
- 三段录像的内容（`replay-re.md`）：`Tutorial1.qbv` 地图 311 普通对战，`Tutorial2.qbv` 抢包子 806，`Tutorial3.qbv` 踢炸弹 704，都由 QQ 7354982 录制。它们是“高手玩家录像”示范，不是关卡本身。
- 宿主：询问框用 `show_msgbox` + `ui_msgBox(0)` 弹出；原生 `OnMsgBoxResult` 包了一层，只截下 `0x2000008`，其他句柄照旧；录像用已有的 `ReplayBattle` 播放，结束回调按上面的规则接下一段。文件名原版写小写 `tutorial1.qbv`，发布包里是 `Tutorial1.qbv`，宿主不区分大小写查找。

## 关卡：Task.txt 任务控制器（宿主未实现）

以下内容来自对 `Client.exe` 的静态阅读。宿主还没有这套解释器，侧车也加载不了规则 9 的地图（`mapdata` 的地图目录排除了 `practice` 家族）。所以现在点“新手任务”时，先弹框说明，再按中途离开处理，走上面的结束流程。

### 控制器

- 控制器类：
  - 虚表 `0x007A2348`，构造函数 `0x005C5CC1`，对象 0xB4 字节，指针存在 `gm+0x56EF4`。
  - GAME_BEGIN 处理函数 `0x005A2089` 只在 `+0x56EEF` 为真、`+0x56F04` 为假时创建它，然后调用虚表 `+8`（`0x005C5F8A`）。
  - 任务表为空时才读 Task.txt（`0x005C6044`）；否则只把控制器重新绑到新场景，所以同一张任务表跨地图沿用。
- 每帧更新：`0x005A3DD9` 调用虚表 `+4`（`0x005C5DF2`），再由它调 `0x005C5F3A`：
  - 当前条状态为 3：进到下一条（`+0x10`，即 `0x005C6187`）；
  - 状态为 2：执行当前条（`+0x18`，即 `0x005C6221`，跳转表在 `0x5C70D6`）；
  - 状态为 1：开始当前条（`+0x1C`）；
  - 任务表为空：调用 `0x005A4181`。
- Task.txt 的读法：按“整数 + 分隔符”连续读，每 10 个整数凑成一条，和换行无关。每条存成 32 字节记录，放在控制器 `+0x6C`。各字段：
  - f0：角色（加上本机 PlayerID）；
  - f1：序号；
  - f2：动作（`+0x70`）；
  - (f3,f4) 和 (f5,f6)：两组（列, 行），像素 = 格 × 40 + 20；
  - f7：毫秒数；
  - f8：另作他用；
  - f9：参数（提示序号、地图号或组数）。
- 控制器上的其他字段：`+0x88` 状态（1 新、2 执行中、3 完成），`+0x94` 本条开始的时间，`+0xAC` 输入模式（2 锁定、4 自由）。
- 原版 bug：本机 id 被加了两次（`0x5C64A1`、`0x5C71A5`），只有本机 id 为 0 时才对。推断教程里本机 id 就是 0。
- `RoutineTask.txt` 程序不读，所有文件里都搜不到这个名字。例程直接写在 Task.txt 里，紧跟在动作 25 那一条后面。

### 动作

| 动作 | 地址 | 作用 |
| --- | --- | --- |
| 1 | `0x5C6294` | 锁定输入，f7 毫秒后让本机停下 |
| 2 | `0x5C62F7` | 强制本机朝方向 0 走（推断向右），走到 (f5,f6) 后瞬移到格心并停下 |
| 3、29 | `0x5C6FBF` | 本机带头像说 `表[f9]`，满 5 秒或按空格结束，然后移除提示 |
| 30 | `0x5C6F15` | 同上，但只能等满 5 秒；结束后在 (f5,f6) 显示目标箭头（`0x5D21E9(1)`） |
| 5 | `0x5C63AB` | 本机瞬移到 (f5,f6)（`0x5AD322`） |
| 6 | `0x5C6425` | 本地分发 0x1389，在 (f5,f6) 生成角色 f0：f9 为 0 时 Role 3、同队，否则 Role 0x19、敌队；泡 2、威力 2，速度 (f7==0)+1；AI 类型在 1501～1504 上为 1，其他地图为 2（`0x5C710A`） |
| 7 | `0x5C6616` | 角色 f0 寻路走到 (f5,f6)（角色虚表 `+0x74`） |
| 8 | `0x5C6687` | 角色 f0 说话，满 5 秒或按空格结束 |
| 10 | `0x5C673B` | 切到地图 f9：`gm` 虚表 `+0x2C`（`0x005A40B3`）用同一份 GAME_BEGIN 重新开局，并重新置 `+0x56EEF` |
| 11 | `0x5C6759` | 替角色 f0 在 (f5,f6) 放泡 |
| 12 | `0x5C67C5` | 角色 f0 说话 5 秒，然后在 (f5,f6) 显示箭头 |
| 13 | `0x5C684D` | 输入自由，直到本机走到 (f5,f6)，然后隐藏箭头 |
| 15 | `0x5C6CAD` | 生成一个同队角色（Role 3）并把它困在泡里，困泡时长加 240000 ms |
| 16 | `0x5C6C12` | 把上一个角色再困一次，并分发 0xFA5 |
| 25 | `0x5C6944` | 读后面 f9 组例程。每组第一条是组头（动作 0，f9 为步数），这一组分给组头 f0 指定的角色。之后进入例程模式（`+0xAD = 1`），不再执行任务表 |
| 27 | `0x5C6E00` | 剧情卷轴，10 秒或按任意键（`0x5A542E`）结束；期间 `gm+0x56EFD = 0`（不画界面层），场景 `+0x4E0F = 1` |
| 28 | `0x5C7045` | 任务卡，5 秒或按任意键结束；场景 `+0x4E10 = 1` |
| 32 | `0x5C6EC1` | 在 (f3,f4) 格心摆放 misc356（推断是酷比），场景 `+0x4E11 = 1` |
| 33 | `0x5C6EA1` | 输入自由，吃齐 9 种道具（`+0xB0 == 9`）后完成 |

例程（`0x5C7185`）循环执行：`0x5AFB86` 推进到下一步，`0x5AFB1A` 回到开头。

- 7：走向 (f5,f6)。走到 (0,1) 就发 0xFBB 判负。原版 bug：另一个判负格 (0,13) 走不到，所以左下角实际不判。
- 0xB：放泡。
- 0x17：等 f7 毫秒后分发 0xFBA（复活）。
- 0x18：等 f7 毫秒。
- 0x1A：瞬移到 (f5,f6)。
- 0x1F：退出例程模式，回到任务表；数据里没有用到。

数据里没有用到的动作还有 0xE、0x15、0x16。其中 0x16 的越界判断永远为假，0x15 会每帧重发 0xFBB，都是原版 bug。

### 输入、提示和画面

- 输入：
  - 规则 9 下，`+0xAC` 不是 4 时，放泡（`0x610BA0`）和移动（`0x6112AF`）都不处理；动作 2 期间改为强制行走。
  - 所以只有动作 13、33 和例程模式下才能自由行动。
  - 空格由 `0x5A4BF7` 判断，任意键由 `0x5A542E` 判断。
- 提示：
  - `0x005AFA3E` 调用脚本 `NotifyAddHint(3, 270, 190, 文字)`。文字超过 100 字节时改用 `(2, 270, 155)`。
  - 超过 200 字节时用 `(1, 270, 120)`，但漏传了文字参数，原版 bug。
  - `0x005AFAE5` 调用 `NotifyRemoveHint()`。
  - 文字表在 `0x007F49C4`，共 29 句（0～28），内容如下。`pve-panel-re.md` 写的“12 句”不完整。
    - 0～9：海王子解救酷比和小倩；
    - 10：“你杀了不该杀的人，现在任务失败啦！”，数据里没有用到；
    - 11～24：道具介绍；
    - 25、26：保卫家园；
    - 27：恭喜进入第三关；
    - 28：“我该怎么办呢？”。
- 图片：
  - 说话头像：misc{360+Role}，位置 (214,239)。
  - 目标箭头：misc355，挂在玩家 `+0x41C`，由 `0x5AC878`、`0x5AEFF7` 绘制，受开关 `DAT_0085DB58` 控制。
  - 剧情卷轴：misc360 在 (160,100,400,400) 内滚动，底图 misc358。
  - 任务卡：misc371～374，位置 (200,180)。
- 吃道具：吃到一种新道具时（`0x60528C`、`0x605386`），在任务表最前面插入一条“角色 本机+1 说话（动作 8）”，提示序号 16～24。
- 死亡（`0x606606`）：同队有人死了就发 0xFBB 判负。在 1501～1504 上，任何角色死后都挂上例程 0x17，10 秒后复活。
- 计时（`0x60D6E5`）：1501～1503 满 240 秒判负；1504 满 70 秒退出例程模式，继续执行任务表。
