# 对话框键盘焦点与输入

2026-11-03。范围：gameUI.dll 焦点入口、Tab 序号和键盘事件传播，以及原生客户端的可用性修正。

## 原版证据

`Win_SetFocus` 有无参数版本（`0x1001C69E`）和控件路径版本（`0x1001C6AC`）。路径版本查控件后直接调用焦点管理器 `0x1003027D`，没有“改选后代输入框”的包装逻辑。管理器把目标保存到 `+0x2AC`，发送旧/新焦点通知。

`0x10028794` 在目标的父控件 `+0x110` 写入当前控件的 `+0x10C`。结合 `0x1002745C` 可确认这是 **groupstop/Tab 停靠序号**：后者找大于当前序号的最小子项，找不到就回到最小序号。此前将它描述成“上次焦点子对象”不准确，更不能由此推断字符会自动转发到编辑框。

管理器 `0x1003084B` 等键盘路径把消息交给当前焦点对象。通用控件的键处理 `0x1002AD34` 优先处理自身的 Tab、Enter、Escape 回调，否则向父控件传播。未找到对话框按 `+0x110` 自动向后代转发普通文字的路径。

原版加好友脚本（uiMain 的两个添加入口）顺序是：清空邀请输入框→`Win_SetFocus(uiAddFriendDlg+'.text')`→`ui_setCapture(uiAddFriendDlg)`。后者再次执行显示、**聚焦对话框**、设置捕获。这个顺序覆盖了先前选择的输入框。

## 原生客户端修正

按此前“修正明显原版 bug、保持界面和协议”的约定，宿主在收到“聚焦父控件”时，若当前已明确选定它内部可见、启用、可编辑的输入框，就保留编辑焦点。捕获仍归对话框；点击具体按钮仍会聚焦按钮，切换到别的对话框不会保留无关输入框。

Tab 默认遍历限制在当前捕获对话框内；Enter/Escape 沿控件祖先寻找回调，并在模态边界停止，不能触发背后大厅的聊天/快捷键。系统消息框的确认、取消保持优先处理。

这是可用性修正，**不声称 Windows 原版已经实现了同样的自动焦点保留**，也未修改转换后的原版脚本。

## 验证

- 四项独立测试：原脚本先子后父顺序保留输入并可输入/退格；Tab 不离开捕获对话框且 Enter/Escape 由对话框处理；其他对话框不保留无关输入；没有 Enter 回调的模态框不会激活后台大厅。
