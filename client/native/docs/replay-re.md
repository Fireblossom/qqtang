# 录像：观看与保存（.qbv）

2026-11-17，静态逆向 `Client.exe`。代码：
- 文件读写 `qqtclient/qbv.py`
- 播放会话与原生函数 `qqtclient/battle/replay.py`
- 侧车回放模式 `cmd/qqt-battle-sidecar/replay.go`
- Go 解码器 `internal/game/qbv`（早已存在）

## 文件格式

整个文件是一段 zlib 流，解压后为小端，依次是：

1. `"vaqq"`、版本 1。
2. 四个头部 DWORD：
   - 第 0 个未识别。
   - 第 1 个是录制者的 QQ 号。
   - 第 2 个是录制者的 PlayerID（三个教程都是 6，对应 QQ 7354982）。
   - 第 3 个是人数。
3. 人数 + 2 个引导对象，每个为（长度、schema、数据）：
   - GAME_BEGIN `0x0FA1`：GameBeginData，不带 2 字节长度前缀。
   - GAME_OVER `0x0FBB`：NOTIFY_GAME_OVER 体。2007 年的录像在末尾缺少 GameMode 字节，Python 解析器本来就容忍。
   - 每人一个 PLAYER_INFO_IN_ROOM_OLD `0x042A`，和房间里的玩家记录是同一结构。`net/room.read_room_player` 能完整读出，`encode_room_player` 写回的结果与教程文件逐字节相同。
4. 事件数，之后每条事件为（时间、schema、长度、数据、三个 DWORD）。
   - 数据是原样的大端对战消息，录制方发出和收到的都在里面：移动 `0x0FA2`、放泡、仲裁结果、拾取、死亡、使用道具、踢泡、表情等。
   - 末尾三个 DWORD 看起来是按发送方递增的序号和客户端时钟，回放不需要；宿主写入（序号、客户端时钟、0）。

## 观看（`PlayRecord` `0x0048C910` → `0x005A36CE`）

- 菜单“录像”（`SC_ClickWatchVedioBtn` 只是统计）打开脚本的文件浏览框。浏览框从 `os_getmoduledir()\Record` 开始，用 `os_listdir`、`os_isdir` 列出 `.qbv` 文件；盘符来自 `win32_GetLogicalDrives`，宿主只报 Z:，与 Wine 一样把整个文件系统映射为 Z:。按“确定”后调用 `PlayRecord(路径)`。
- 原版据文件重建场景，再按时间推送每条消息。`0x005A3C7F` 先执行 `showRecordRecorder(0)`、`showRecordPlayer(0)`，回放时再执行 `showRecordPlayer(1)`，并调用 `setRecordQQNumber` 显示录制者的号码。
- 面板按钮：
  - 暂停：播放对象 +0x3B3894 置 1（`0x005A3F76`）。
  - 继续：置 2，速度恢复 1（`0x005A3F9D`）。
  - ×2/×4：置 2，速度设为 n（`0x005A3FD6`）。
- 宿主做法：侧车新增回放模式，直接解码文件建局。它是一个没有本机玩家、没有网络的非仲裁方，录像里的每条消息到时间后，经已有的远端消息处理（`applyRemote`）应用，仲裁结果因此和当时一样生效。
- 文件不记录每条消息的发送者，回放按以下规则推断：
  - 玩家消息以发送者的 PlayerID 开头，按它判断。
  - 不被接受的再按仲裁方判断。
  - 仲裁方自己的消息不会被应用两次。
- 2007 年的教程录像在墙里藏了现在道具表里没有的 24040。回放把它当作只由服务端计数的规则道具（新增导出函数 `battleengine.PickupSceneSupported`），这样其他道具在洗牌后的位置不变。
- 播放时钟由宿主推进（暂停、×2、×4），侧车的 `step` 带 `replay_ms` 参数。最后一条消息过后 1 秒，用录像里的 GAME_OVER 显示结算，12 秒后（或按键、点击）回到原来的界面。播放中只有 F8 名牌开关有效。
- 浏览框的列表底图是白色，脚本却用 `lightColor`（白）写文件名，看不见。宿主把这 12 个文件名标签改为深色字。这是宿主偏离，原版是否同样看不见没有核实。

## 保存（`BeginRecord` `0x00534080`、`StopRecord` `0x005340B0`）

- 两个函数都只是设置标志 `+0x56EEC`（`0x005A4069`）。若此时已处于结束状态，`BeginRecord` 立即写文件（`0x005A35FB`）。所以原版其实每局都在录，只在结束时按标志决定写不写；中途按“保存录像”，保存的也是整局。
- 文件名：`Record/<QQ号>/<年>年<月>月<日>日<时>时<分>分.qbv`（`0x007F21AC`，不含秒，同一分钟内会覆盖）。
- 提示语函数 `0x005C81D7` 在最终版里是空的，“录像已启动”等文字不显示。
- 在线对战一开始就显示“保存录像”按钮；练习和教程不显示（`0x005A3C7F`）。
- 宿主做法：
  - 侧车在在线对战中记下每条收发的消息，包括 UDP 收到的、本机排队发出的和转来的 TCP 游戏事件，时间取当时的场景时钟，保证不递减。新增的 `record` 命令返回这份列表。
  - 收到 GAME_OVER 时，若标志为开就写文件：GAME_BEGIN 取开局负载去掉长度前缀；玩家记录取房间成员编码出的 PLAYER_INFO；服务端 AI 不在房间成员里，按开局角色补一份不穿装备的记录。
