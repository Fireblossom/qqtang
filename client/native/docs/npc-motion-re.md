# NPC默认浮点移动与完整网络预测

2026-11-04，接续 `npc-navigation-re.md`、`npc-rule-dispatch-re.md`。规则8仲裁NPC现保留float32坐标，按NPC速度表的原始标量积分，使用 `0x005CFC10` 的默认单轴移动/滑角分支；不再将三档先取整成123px/s。普通玩家的整数引擎路径没有切换。

## 原版执行路径

`0x005F3D0A` 读取NPC速度档、`0x005C452B` 速度表、规则角滑容差，先调 `0x005CF8D9→0x005CFC10` 位移，再用 `0x005CFB67` 同内核四方向试算掩码，最后 `0x005CF9B8` 预测角点/终点。命令walk位与实际是否位移分开；站立时不位移，受阻时仍可发送walk。

默认内核处理当前格出口方向、单次最多40px、前沿19px、轴向目标中心截断、垂直于命令方向的滑角及阈值10。其“还在当前格”快速分支比较候选中心与**候选中心加前沿方向19px**，不是正负两侧都查；人在已有障碍内部时，两种写法会不同。格心判断部分先截断像素，滑角到目标剩余距离也先截断再取绝对值，保留这些原生边界。

查询入口 `0x005B7999` 下层 `0x005B7D1B` 读取signed short坐标和低字节方向。尤其Up分支，参数高16位可残留指针；探针不能直接把完整32位值当坐标，否则会把可通判成越界。普通左上绕角的对角检查传Right，按原汇编保留。

## 浮点精度

GFX设备创建 `0x10003A23` 路径的标志为顶点处理位再OR4，没有OR2（FPU_PRESERVE）。Direct3D在该条件下使用单精度、最近舍入；这是原版设备初始化与[微软浮点控制说明](https://learn.microsoft.com/en-us/windows/win32/dxtecharts/top-issues-for-windows-titles)共同支持的执行环境，尚未在本机运行Windows进程测控制字。

探针显式设置x87控制字007F，并恢复每次ftol调用前的控制字。位移乘法必须逐项float32取整：`float32(float32(dt*speed)*0.04f)`，不能把整串提升成double后只取整一次。连续跨128px附近时，后者会差一个float32位。角色27从(220,260)向右走50×20ms，原版与移植均为x=343.0802307128906；整数视图仍显示343。

## 网络预测与跟随

`0x005CF9B8` 从当前浮点位置以25ms步长反复运行同内核，直到**截断像素坐标不变**，不以float坐标是否改变作为结束条件。记录第一次垂直位移之前的位置为Corner，最终End仅沿命令主轴将个位9/1修正到邻近10的倍数。

开放15×13控制图中，从(220,260)向右预测到(580,260)，不是下一格(260,260)。有上侧障碍时，先滑到y260，再沿x走到580；Corner记录滑角开始处。侧车现在发送完整Corner/End并在角点变化时立即发新样本，保留walk；跟随端按初始主轴段→垂直修正→最后主轴段消费行程，避免直接穿过拐角。跟随速度也使用原始NPC标量；其以报文时间戳计算路程的适配由组合测试验证，未单独宣称完整原版网络控制器逐帧等价。
