# NPC收包队列与两种位置回正

2026-11-04，接续 `npc-remote-path-re.md`。默认NPC、命名Boss和探险NPC的接收端已从最新记录/时间戳重装近似，改为原版接收队列、记录选择、丢序列对齐与两种回正。

## 实际执行的入口

`tools/probe_npc_remote_queue.py` 将20字节、已经网络解码的小端PLAYER_MOVESEQ交给原版 `0x005AF44D`，由其展开为0x34字节记录并调用 `0x005D0945`。随后执行整个 `0x005D09D6` 帧更新，保留原版链表插入/替换、记录选择、消费、移除旧记录、位置setter和校正函数；没有给队列选择函数或状态转换打桩。

图形、NPC身份/控制方、空世界及CRT abs/ftol桥是与前轮相同的受控依赖；x87使用PC24。初始位置为(300,260)，远端对象由真实 `0x005D086B` 构造。这里验证的是解码后的角色接收控制器，不包含UDP可靠传输层、QQTPPP重传或源Win32整局。

## 核对结果

- 时间戳必须严格大于最后接收值，等值/旧值都丢弃；它不是报文的未来执行时间。首条可消费记录到达后，在下一角色帧对齐其位置，当帧不按记录年龄再前进。此前按TimeStamp等待切姿态的测试和实现已纠正。
- 同序列、更新的时间戳覆盖队列尾记录。若它也是当前序列，只立即更新Corner/End；不重装当前位置、walk、方向、速度标量或拐角阶段。
- 新序列保留到队列中，每帧寻找与当前序列不同的最早记录。与当前不连续时，或最新序列的无符号差超过4时，执行位置对齐并移除目标之前的旧记录。序列从wire有符号short展开，保留其边界行为。
- `WalkAndDirection`低四位是方向，bit4是walk，bit5是强制位置记录。`0x005D0A65`扫描强制标记、清标记、装载并对齐；它与最新记录超差分支的优先次序也保留。
- 正常行走记录落在当前位置后方时可进入模式2，以该记录的玩家表速度回正；部分前方记录会推进旧保持段后再对齐新起点。
- 新停止记录在前方时可继续旧行走，进入1px阈值后才消费停止；后方不超过40px时进入模式1，以0.016px/ms回正。回正期间不额外累加保持时钟。
- 停止回正中再收到行走记录时有垂直/主轴修正分支。保留 `0x005D0C7E` 对新垂直行走的怪癖：它在该分支始终选择+X回正，不按目标左右选方向。

各分支位置均逐帧float32累加；正常保持段继续使用上一轮核对的拐角状态机。

## 基准与接入

```sh
.venv/bin/python tools/probe_npc_remote_queue.py /path/to/client-patched
```

`npc_remote_queue_v848.jsonl` 共458组接收/帧序列，15594次状态快照，其中14641次帧更新。覆盖四方向、1/2/3/10档、前后1/2/8/9/10/40/41/81px、walk/stop、接收合并、强制记录、同序列80px追差、序列与时间戳边界、Corner更新及回正中重启。快照中模式0/1/2分别出现13418/1168/1008次；不以这些次数代替分支覆盖率。

Go逐项比较位置和缓存标量的float32位模式、队列长度、最后接收时间、walk/方向/档位、拐角阶段、保持时钟、当前序列、回正模式及是否消费记录。相同序列也全部经正式 `receiveNPCMove/interpolateBoxNPC` 入口回放，另验证同一帧重复调用不多消费一条记录。

正式接入时，收到报文只入队；箱子NPC先更新旧图片，再执行收包控制器，只有实际消费记录时才设置行走/停止动作。同序列更新和重复包不会抹掉后来选择的冰箱动作。控制器每帧从共享角色位置取值，兼容控制权变化后的浮点运动与旧整数运动；另有回归覆盖，未把此单元回归冒称为完整原版接管对照。Boss与探险接收入口共用此队列，移除之前额外按序列大小丢包的近似，仍由原版时间戳规则和消费规则决定。

相关侧车/引擎全套与Mac、Windows/386构建通过。累计NPC/共用模型记录7145条（6687+458）；15594是这些序列内的快照数，不重复加总。

发送侧后续已核对并改为原版共享历史、状态变更序列与无固定心跳，见 `npc-publish-re.md`；本轮队列对照自身没有包含发送端。源Win32整局、完整可靠传输层与所有特殊角色状态也不在本轮等价结论内。
