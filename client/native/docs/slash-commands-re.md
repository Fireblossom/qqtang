# 聊天斜杠命令（QQTSection.dll 静态逆向）

范围：玩家在大厅（小区）或房间的聊天框里输入的 `/xxx` 命令。只覆盖 QQTSection.dll 里的解析与执行，以及它们发出的网络请求（NetCenter.dll）和少量收包方逻辑。`/M`（0x11）、`/U`（0x12）的密聊屏蔽列表已经清楚，本文跳过。

标注：**[证实]** 表示从伪 C 或数据里直接读到，关键数值用 capstone 核对过；**[推断]** 表示有依据但没追到底；**[未知]** 表示没查清。地址都是虚拟地址：QQTSection.dll 基址 `0x10000000`，NetCenter.dll 基址 `0x10000000`。中文文本是按 GBK 从 DLL 字节读出来的。

记号：

- `S` 是 QQTSection 的 `CMySection` 对象。网络侧接口 `XSection` 在 `S+0xBF30`，虚表 `0x10054928`；`XSection2` 在 `S+0xBF34`，虚表 `0x100548E8`。
- `R` = `*(S+0xC558)`，是当前房间对象。`R+4` 是房间状态：0 表示不在房间，1 表示在房间里等待，2/3/4 是游戏中的各种状态 [推断]。
- `ID` = `S+0x1C8`，是本人的 Identity 位。`/whoami` 构造本地资料时，把它填进 FindFriend 应答的 Identity 字段 [证实]。
- 本人 UIN 在 `S+0x1A8`（多数地方用它）和 `S+0x198`（FindFriend 和婚姻请求里用它）[证实]。`S+0x2588` 也被当作"自己"来比较 [推断：是另一份本人 UIN]。
- `S+0x192` 是 ServerID，`S+0x194` 是 SectionID。这一点由邀请字符串的格式 `..._serverid(%d)_sectionid(%d)...` 证实 [证实]。
- "比赛频道"指 `S+0xC768 == 1`，由 `FUN_10002491` 判断。证据是相关提示文字"要在比赛频道中，才能执行此命令!"和"比赛频道中，不能自选房间" [证实]。
- 网络接口：`S+0x2C` 是服务注册表，虚表 `+0x14` 是 QueryInterface。GUID `ec7bdccd-d0cf-48ad-ba4e-13a3c84461aa`（QQTSection `0x10054340`）是 NetCenter 的发包接口，NetCenter 里它在对象 `+0x24`，虚表 `0x1002F764` [证实]。下文写成 `net+0xNN`。
- 聊天界面接口：GUID `142027df-4f0c-47f1-8c1b-bf8db7b9db51`（`0x10054380`）。
  - `+0x18(channel, 0, text, colour)` 往聊天框加一行。
  - `+0x10(pyexpr)` 执行一段界面脚本，例如 `UpdateUIWisper()` [证实调用；"执行脚本"是推断]。

## 0. 结论摘要

1. 入口 [证实]：
   - 界面脚本调 Client.exe 的原生函数 `SectionChat(dest, text)`（`0x0048E5B0`）或 `RoomChat(dest, text)`（`0x0048E2E0`）。
   - 它们分别走 `XSection+0xE8` 和 `+0xEC`，即 QQTSection 的 `FUN_10020433` 和 `FUN_100204CE`。
   - 再进入 `FUN_10028D58`（小区聊天）或 `FUN_100291EA`（房间聊天），或者小喇叭的 `FUN_100087FA`。
   - 三条路都调 `FUN_10023BD1`：去掉首尾空白，长度不超过 0x7FF，然后调 `FUN_10024DCB`。
   - 一行被识别成命令后，**一律不当作聊天发给服务器**。
2. 普通玩家可用的命令有 `/W` `/R` `/IN` `/JOIN|/GO` `/AUTOJOIN` `/AR` `/WHO` `/whoami` `/mute` `/unmute` `/refuse|/rf` `/unrefuse|/urf` `/DONTADDME` `/CANADDME` `/KINCHAT` `/ki` `/c2c`，外加已知的 `/M` `/U`。
   - 在比赛频道里，除非身份带 `0x100` 或 `0x200`，只剩 `/WHO` `/W` `/R` 和 0x0F～0x17 这一段：`/mute` `/unmute` `/M` `/U` `/whoami` `/refuse` `/unrefuse` `/DONTADDME` `/CANADDME`。
3. 普通命令要么只改本地状态，要么复用已有的协议命令，**服务器不需要新增命令**：
   - 0x6C 跨小区聊天，消息内容是 `in_…`、`inresult_…`、`wisper_…` 这类小格式字符串；
   - 0x68 进入房间；
   - 0x8A 快速加入；
   - 0x67 FindFriend；
   - 0x107 婚姻信息；
   - 0x72/0x73 准备/取消准备；
   - 0xBA 家族邀请；
   - 0xBE 家族聊天。
4. 只有比赛裁判和管理员的命令用到了 `commands.go` 里**没有**的命令号：
   - `/it` → **0x9E**（schema 0x42D）；
   - `/ct` → **0x9F**（schema 0x42C）；
   - `/KICK`、`/KICKOFF` → **0x321**（schema 0x1F42）；
   - `/FORBID`、`/NOLOGIN` → **0x323**（schema 0x1F45）；
   - `/DISMISS` → **0x325**（schema 0x1F48）；
   - `/INVISIBLE` → **0xAA**（schema 0x1F55）。
   - `/LODGE` 根本不走游戏服务器，而是写进本机共享内存，交给外部的"网管程序"。
   - `/SYSMSG` 在这个版本里被禁用了，执行函数直接返回 0。
5. 原版 bug [证实]：`/JOIN n 密码` 的密码是在**发包之后**才拷进请求结构的，所以服务器永远收不到密码。

## 1. 调用链 [证实]

```
Python UI ──SectionChat(dest,text)──▶ Client.exe 0x0048E5B0 ──XSection+0xE8──▶ FUN_10020433
          ──RoomChat(dest,text)────▶ Client.exe 0x0048E2E0 ──XSection+0xEC──▶ FUN_100204CE
FUN_10020433: type==1 → 小喇叭 FUN_100087FA；否则 FUN_10028D58（小区聊天）
FUN_100204CE: 比赛频道且 FUN_1000A6B9(R)==0 → FUN_10028D58；否则 FUN_100291EA（房间聊天）
FUN_10028D58 / FUN_100291EA / FUN_100087FA → FUN_10023BD1(…, text, …)
FUN_10023BD1: len>0x7FF 丢弃；Trim；sprintf("%s")；
              r = FUN_10024DCB(line)；r==0 且 FUN_100239E9(line)!=0 → 当作普通聊天继续发送
```

`FUN_10024DCB(line)` [证实]：

1. 调 `FUN_1003A557(&cmd, line)` 解析，结构见 §2。
2. 返回 0，说明不是命令：
   - 再查会员表情 `FUN_10024F39`。没有会员身份（`ID & 0x2000` 为 0），而文本里任意位置出现 24 个会员表情 `/m00`～`/m23` 之一（表在 `0x10064560`），就打印 `您现在还不是QQ堂会员，请加入会员后再使用会员表情`，并且不发送。
   - 否则返回 0，交给普通聊天发送。
3. 是命令但 `cmd.id == 0`：打印 `输入无效命令`。
4. 其余：`FUN_10025027(&cmd)` 返回 0 时打印 `输入无效命令`。
   - 很多出错分支**先打印自己的错误、再返回 0**，所以会连出两行，例如"不能和自己说悄悄话"后面跟"输入无效命令"。下文标注为"返回 0"的就是这种情况。
5. 是命令时 `FUN_10024DCB` 一律返回 1，这一行不再发出去。

输出约定 [证实]：

- 系统行都调聊天界面 `+0x18(channel, 0, text, 0xB8FF79)`。
- `channel = FUN_1000A6BD(R)`：`R+4==1` 时为 2（房间），`R+4` 为 2/3/4 时为 3，其余为 1（大厅/小区）。下文写成"当前频道"。
- 少数分支写死 channel 2，或者用别的颜色，会单独注明。
- 管理员相关的行，颜色由 `FUN_1001F8BD(ID, 0)` 决定：0x40000 → `0xFF5CE6`；有 `0x30006` 任一位 → `0x5DFFE6`；否则 `0xBDEAFF`。

## 2. 解析 `FUN_1003A557` [证实，关键处核对过汇编]

### 2.1 解析结果结构（0x828 字节，先清零）

| 偏移 | 含义 |
| --- | --- |
| `+0x00` | 命令 ID，由 `FUN_1003A0AD` 给出 |
| `+0x04` | `arg1 = atoi(tok[1])` |
| `+0x08` | `arg2 = atoi(tok[2])` |
| `+0x0C` | `argCount`。很多分支**不写它，保持 0**，见下表 |
| `+0x10…` | 只有 `/it` 用：`atoi(tok[1..])` 依次存成 int 数组 |
| `+0x28` | 文本参数（`sprintf("%s")`，最长 0x7FF） |

### 2.2 切词与判定

- 按单个空格 `' '` 切词（`FUN_1003A48F`），连续空格会被跳过。
- 是命令的条件：至少 1 个词，第一个词以 `/` 开头，并且第一个词**不以** 144 个普通表情代码中的任何一个开头（表在 `0x10063FB4`：`/m00`…`/nan`，用 `CString::Find(...)==0` 判断）。
- 不是命令时返回 0。表情代码和命令词之间没有前缀冲突（已核对）。
- 命令词用 `_mbsicmp` 比较，**不区分大小写**。

### 2.3 各命令 ID 的参数规则

下表 N 是词数（含命令词）。"合法"指保持 ID；"非法"指把 ID 置 0，结果是打印 `输入无效命令`。

| 命令（ID） | 规则 |
| --- | --- |
| `/it`（0x18） | N≥2：`+0x10..` = 各参数的 atoi，`argCount = N-1`；N<2 非法 |
| `/ct`（0x19） | N==2：`arg1`，argCount 保持 0；N==3：`arg1, arg2, argCount=2`（经 `LAB_1003a90f` 落到通用分支，arg2 被忽略）；其余非法 |
| `/AUTOJOIN`（4）`/AR`（0xE）`/mute`（0xF）`/unmute`（0x10）`/whoami`（0x13）`/DONTADDME`（0x16）`/CANADDME`（0x17） | N==1 合法；N==2/3 也合法，参数忽略；N≥4 非法 |
| `/WHO`（2）`/IN`（1）`/KICK`（9）`/DISMISS`（0xC）`/M`（0x11）`/U`（0x12）`/INVISIBLE`（0x1A）`/ki`（0x1C）`/c2c`（0x1D） | N==2：`arg1`，argCount 保持 0（汇编 `0x1003A7B9` 只写 `+4`）；N==3：`arg1, arg2, argCount=2`；其余非法 |
| `/refuse` `/rf`（0x14）`/unrefuse` `/urf`（0x15） | N==1 合法（argCount=0）；N==2：`arg1, argCount=1`；N==3：`arg1, arg2, argCount=2`；其余非法 |
| `/SYSMSG`（0xB）`/R`（6） | N≥2：`+0x28` = `tok[1..]` 用空格连接；N==1 非法 |
| `/W`（5） | N==2 且 `tok[1]` 不区分大小写等于 `off`：`+0x28 = "off"`；N==2 的其他情况：`arg1`；N==3：`arg1, arg2, argCount=2`（**没有文本**）；其余非法 |
| `/KINCHAT`（0x1B） | N==2 且 `tok[1]` 是 `off` 或 `on`：`+0x28` 存这个词；N==2 的其他情况合法，但执行时落空，返回 0；N==3 合法但同样落空；其余非法 |
| `/LODGE`（7）`/JOIN` `/GO`（3） | N≥2：`arg1 = atoi(tok[1])`，`+0x28` = `tok[2..]` 用空格连接；N==2 时 `argCount=1`，否则 `argCount=2`；N==1 非法 |
| `/FORBID`（8）`/NOLOGIN`（0xD）`/KICKOFF`（10） | N==2：`arg1, argCount=1`；N==3：`arg1, arg2, argCount=2`；其余非法 |

## 3. 执行前的比赛频道门槛 `FUN_10024FC8` [证实]

满足下列任一条件才继续执行，否则返回 0（打印 `输入无效命令`）：

- 不在比赛频道（`S+0xC768 != 1`）；
- `ID & 0x300` 不为 0（`S+0x1C9 & 3`）；
- `id == 2`（`/WHO`）；
- `id` 为 5、6（`/W` `/R`）；
- `id` 在 0xF～0x17 之间。

## 4. 身份位（`ID = S+0x1C8`）

| 位 | 含义 | 依据 |
| --- | --- | --- |
| `0x2000` | QQ堂会员，可用会员表情 | [证实] |
| `0x100` / `0x200` | 比赛频道的特权身份（`/it` `/ct` 需要；比赛频道里不受上面门槛限制；`0x700` 任一位可在比赛频道里自选房间）。推断是"裁判"，因为另有 `[裁判 %u]%s` 文本，颜色也和网管一样 | [推断] |
| `0x100000` | 隐身中。登录或 0xAA 应答后，`S+0x28 = (Identity >> 20) & 1` | [证实] |

管理员角色：多数函数先把 ID 归一成"最高的一个角色"。优先级是 `0x40000 > 0x20000 > 0x10000 > 0x2 > 0x4`，个别函数把 `0x4` 归成 0。

- 提示文字里，角色为 0x40000 时自称 **网管**，其余自称 **巡查员** [证实]。
- 级别名称推断为：0x20000 高级巡查、0x10000 巡查、2 和 4 是更低的两级。

`/FORBID` 的子权限 `FUN_10026C90(ID, need)`：角色 2 → `need & 1`；0x10000 → `& 0x23`；0x20000 → `& 0x2B`；0x40000 → `& 0x3F`。`need` 取值：1 表示禁言 1 小时，2 表示禁言 N 小时或解除，4 表示永久禁言 [证实]。

## 5. 普通玩家命令

### 5.1 `/W <uin>` 或 `/W off`（ID 5）：设定密聊对象 [证实]

- **`/W off`**：`FUN_1002AF1D(0, NULL)` 清除密聊对象（`S+0xC5B0 = 0`，名字清零），同时清除家族聊天模式（`S+0xC5DC = 0`）。然后执行界面脚本 `UpdateUIWisper()`。
- **`/W <uin>`**：
  - `uin ≤ 10000`：打印 `输入的玩家QQ号不正确`，返回 0。
  - `uin` 是自己：打印 `不能和自己说悄悄话`，返回 0。
  - 否则 `FUN_1002AF1D(uin, NULL)`：`S+0xC5B0 = uin`，`S+0xC5B4` = 十进制 uin 字符串（最长 0x27），然后 `UpdateUIWisper()`。
- **命令本身不发包**。`/W uin 消息` 的第三个词只会被 atoi 成 arg2，消息不会发出去。
- 之后普通的小区聊天（`FUN_10028D58`）就变成密聊：
  - 消息长度不超过 0x100；
  - 发 **0x6C 跨小区聊天**，内容为 `wisper_uin(<本人UIN>)_content[<len>](<text>)`；
  - 本地回显 `悄悄的说: %s` 之类的文字（`0x10062268`、`0x100623C4`、`0x100623E8`、`0x10062404`）[证实发包；回显的具体格式只读了伪 C]。

### 5.2 `/R <文本>`（ID 6）：回复最后一个对你说悄悄话的人 [证实]

- 回复对象是 `S+0xC584`（UIN）和 `S+0xC588`（名字），由收到 `wisper_` 消息时写入 [推断]。
- 对象为 0：打印 `没有回复对象`，返回 0。
- 文本超过 0x80 字节：返回 0，打印 `输入无效命令`。
- 否则发 **0x6C 跨小区聊天**（`XSection+0x64` → `net+0x58` → NetCenter `0x1001659C`，command 0x6C、schema 0x3F4）。请求结构 0x208 字节，和 `chat.go` 的 AcrossSectionChatRequest 一致：

| 偏移 | 内容 |
| --- | --- |
| `+0` | UIN = `S+0x1A8` |
| `+4` | Time |
| `+8` | ServiceID = 0 |
| `+0xC` | DestinationPlayerID = 0 |
| `+0xE` | DestinationPlayerUIN = `S+0xC584` |
| `+0x12` | 长度 |
| `+0x14` | 内容 `wisper_uin(<本人UIN>)_content[<len>](<text>)` |

- 本地打印 `回复玩家%s[%u]: %s`（名字、UIN、文本），频道和颜色同上。

### 5.3 `/IN <uin>`（ID 1）：邀请玩家进入自己的房间 [证实]

检查顺序：

1. `R` 不是"房主"状态（`FUN_1000B399` 为假，推断是 `FUN_1000B847` 找房主座位），且房间类型 `S+0xC8B4 == 4`（推断是聊天室）：打印 ` 您不是该聊天室房主，不能进行邀请操作。`（频道 2），返回 1。
2. `R+4 != 1`：在当前频道打印 `只有在房间中才能邀请其他玩家`，返回 1。
3. `uin ≤ 10000` 或 `uin` 是自己：没有任何分支处理，最后返回 0，打印 `输入无效命令`。
4. 对方已经在本房间（`FUN_1000DAEA`，8 个座位）：打印 ` 您要邀请的玩家已经在房间中。`（频道 2）。
5. 防刷：`S+0xC794` 链表里存着 `{uin, 到期时间}`。当前时间小于到期时间就打印 `不能频繁邀请同一玩家, 邀请失败, 请稍后再试`（频道 2）。否则把到期时间设为 `now + 5000`。时间来自注册表 `+0x28`，单位未知，按 ms 算是 5 秒 [推断]。
6. 发 **0x6C 跨小区聊天**。头部同 5.2，目标 UIN 是 `uin`。内容是：
   `in_uin(<S+0x1A8>)_serverid(<S+0x192>)_sectionid(<S+0x194>)_roomid(<R+0x70>)_roomflag(<R+0x87>)_password[<len>](<R+0x8A 的 16 字节密码>)`
7. 打印 `您的邀请已经发出。`（频道 2）。

收方的处理（`FUN_10026EFF`，跨小区通知 0x420 的处理函数）见 §8。

### 5.4 `/JOIN <n> [密码]` 或 `/GO <n> [密码]`（ID 3）：进入列表里的第 n 个房间 [证实]

- 已经在房间里（`FUN_1000CED8(R) != 0`，即 `R+4` 为 1 或 2）、`n == 0`、或 `n-1 ≥ 房间数`（`S+0x9AB6`）：返回 0。
- 取房间记录 `FUN_1003CF76(S+0x4970, n, rec)`：每条 0x34 字节，n 从 1 开始，`rec+0x2A` 是 RoomID。
- 请求结构 0x1B 字节：

| 偏移 | 内容 |
| --- | --- |
| `+0` | UIN = `S+0x1A8` |
| `+4` | Time |
| `+8` | RoomID（2 字节，取 `rec+0x2A`） |
| `+0xA` | RoleID = `S+0x1E6` |
| `+0xB` | 16 字节密码 |

- 交给 `XSection+0x7C`（`FUN_1001DEAD`）：
  - `S+0x1A0 == 0` 或 `S+0xC560 != 0`：返回 0，不发送。
  - 在比赛频道且 `ID & 0x700 == 0`：打印 `比赛频道中，不能自选房间`（频道 2），返回 1。
  - `S+0x1A0 ≤ 1`：打印 `正在读取房间信息，请稍候。`（频道 1）。
  - 否则先在房间对象里记下房间名和密码，然后发 **0x68 EnterRoom**（`net+0x64` → NetCenter `0x1001715F`，command 0x68、schema 0x3F7）。这和 `enter_room.go` 的 27 字节请求一致。
- **bug**：有密码参数时（argCount==2），`strncpy(+0xB, 文本, 15)` 在 `call [ecx+0x7C]` **之后**执行（`0x10025EB5` → `0x10025ECC`），所以发出去的密码永远是空的。移植时要决定是否照搬。

### 5.5 `/AUTOJOIN`（ID 4）：快速加入 [证实]

- 已经在房间里：返回 0。否则调 `FUN_1002475F`：
  - 必须 `R` 不在房间里且 `S+0xC560 == 0`；
  - `S+0x1A0 < 2`：打印 `正在读取房间信息，请稍候。`（频道 1）；
  - 否则发 **0x8A JoinRoom**（`net+0xE8` → NetCenter `0x10019695`，schema 0x41D）。9 字节：`{UIN=S+0x1A8, Time, GameType=S+0xC8B4}`，和 `join_room.go` 一致。

### 5.6 `/AR`（ID 0xE）：切换自动准备 [证实]

- 配置接口 GUID `99dd9023-19ff-4ec0-aa8d-09ef75568b3f`（`0x100543E0`）：
  - 先用 `+0x1C(uin, "autoready", &v, &len)` 读出旧值；
  - 再用 `+0xC(uin, "autoready", 1-v)` 写入。这是按本人 UIN 存的本地设置 [推断：保存在本机]。
- 如果 `R+4 == 1`，调 `FUN_1000A1AB(R)`。它在以下条件都满足时调用"准备开关" `XSection+0x15C` → `FUN_10022FB1`，发 **0x72 Ready**（schema 0x402）或 **0x73 CancelReady**（schema 0x403）：
  - 不在比赛频道；
  - 房间类型（`R` 虚表 `+0x68`）不等于 4；
  - `FUN_1000CE7D` 为假；
  - 刚读到的 autoready 为真；
  - 自己不是房主（`FUN_1000B847 == 0`）[推断]。
- 打印 `设置自动准备`（新值为 1）或 `取消自动准备`。

### 5.7 `/WHO <uin>`（ID 2）和 `/whoami`（ID 0x13）：查看玩家资料 [证实]

- `/WHO` 要求 `uin > 10000`，否则返回 0。`/whoami` 用本人 UIN `S+0x1A8`。
- 两者都调 `XSection+0xF0` → `FUN_10020917`。这和原生函数 `FindFriend(uin)`（Client.exe `0x0048EAB0`）走的是同一个函数，所以**行为和界面上"查找好友/查看资料"完全一样**。
  - 先通知界面（接口 `0x10054450` 的 `+0x64` 或 `+0x8C`，取决于房间状态）。如果对方在本小区玩家表里，就用本地数据填一份资料给界面（接口 `0x10054430` 的 `+0x20`）。
  - 目标是自己（与 `S+0x198` 比较）：在本地拼一份 FindFriend 应答（`0x2463` 字节，包括 Identity、房间、物品等），直接交给应答处理 `XSection+0x60`（`FUN_1001D126`），**不发 FindFriend**。
  - 否则发 **0x67 FindFriend**（`XSection+0x5C` → `net+0x54` → NetCenter `0x10015E9E`，schema 0x3F3）。12 字节 `{S+0x198, Time, 目标UIN}`，和 `find_friend.go` 一致。
  - 两种情况都调 `FUN_1003229C`，发 **0x107 婚姻信息**（schema 0xBEF）。
  - 最后通过接口 `0x10054030` 的 `+0xC({uin, 0, 0xFF})` 通知形象模块（QQTAvatar/QQTModules）[推断：预取形象]。

### 5.8 `/mute`（0xF）、`/unmute`（0x10）：拒收或开放所有悄悄话 [证实]

- 设 `S+0xC580` 为 1 或 0。打印 `拒绝他人的悄悄话` 或 `开放他人的悄悄话`，返回 1。
- 只在本地生效：收包函数 `FUN_10026EFF` 在 `0x10026FB1` 看到 `wisper_` 消息且 `S+0xC580 != 0` 时，**静默丢弃**，对方收不到任何回执。

### 5.9 `/refuse` `/rf`（0x14）、`/unrefuse` `/urf`（0x15）：拒绝或恢复房间邀请 [证实]

`/refuse`（不带参数）：设 `S+0xC648 = 1`，打印 `您拒绝了所有玩家的邀请！`。

`/refuse <uin>`：

- `uin ≤ 10000`：`输入的玩家帐号不正确`，返回 0。
- 是自己：`拒绝自己的邀请无意义`，返回 0。
- 否则在 `S+0xC650`（CDWordArray）里没有就追加，打印 `您拒绝了玩家[%u]的邀请！`。

`/unrefuse`（不带参数）：设 `S+0xC648 = 0`，打印 `您不再拒绝其他玩家对您的邀请！`。

`/unrefuse <uin>`：

- `uin ≤ 10000`：`输入的玩家帐号不正确`，返回 0。
- 是自己：`取消拒绝自己的邀请无意义`，返回 0。
- 在列表里：删除，打印 `取消对玩家[%u]邀请的拒绝`。
- 不在列表里：`玩家[%u]不在拒绝列表中`。

只在本地生效：收到 `in_` 邀请时，`S+0xC648 != 0` 或邀请人在列表里，就自动回 `inresult_resultid(1)`（"不接受"），见 §8。

注意：带参数时只有 N==2（argCount==1）才算单个玩家。`/refuse uin x`（argCount==2）会被当成"拒绝所有人"。

### 5.10 `/DONTADDME`（0x16）、`/CANADDME`（0x17）：屏蔽或开放好友请求 [证实]

- `*(S+0x150)+0x50` 设为 1 或 0（`S+0x150` 是好友处理对象，为空时返回 0）。打印 `开启 屏蔽添加好友请求功能` 或 `关闭 屏蔽添加好友请求功能`。
- 只在本地生效：好友处理函数 `FUN_1000FAA9` 在收到 0xA3、`param_4 == 0`（别人发来的加好友请求）时，如果这个字节不为 0，就直接 `return 0`，静默丢弃。

### 5.11 `/KINCHAT on` 或 `/KINCHAT off`（ID 0x1B）：家族聊天模式 [证实]

- **`on`**：
  - 从家族对象（`S+0x30`）取家族 ID（`+0x2C`）和家族名（`+0x3272`），交给 `FUN_1002DE18`。它先清除密聊对象。
  - 家族 ID < 1：打印 `你不在任何一个家族中,无法进入家族聊天`。
  - 否则 `S+0xC5DC = 家族ID`，`S+0xC5E0 = 名字`，然后执行界面脚本 `UpdateUIKinChat()`。
- **`off`**：清除密聊对象，`S+0xC5DC = 0`，`S+0xC5E0` 清零，然后 `UpdateUIWisper()`。
- 之后普通的小区聊天在 `S+0xC5DC != 0` 时改走 `XSection2+0xC` DoTask，任务号 0xC（`FUN_1002CAC9`）。
  - 它组一个 0x210 字节的块：`+0xC` 是长度，`+0x10` 是最多 0x200 字节的文本，交给 `FUN_10016B84`。
  - 推断发的是 **0xBE KinChat**：16 字节头加 512 字节文本，和 `kin.go` 的 `KinChatSlotSize` 一致。
- 其他参数：返回 0。

### 5.12 `/ki <uin>`（ID 0x1C）：邀请玩家加入家族 [证实]

- `uin ≤ 10000`：`输入的玩家QQ号不正确`，返回 0。
- 否则调 `XSection2+0xC`（DoTask，任务 4）→ `FUN_10014141`：
  - 目标是自己，或者本人家族权限 `FUN_100165A3` 不大于 9：静默结束。
  - 否则发 **0xBA OperateKin**（schema 0x177B）。24 字节：

| 偏移 | 内容 |
| --- | --- |
| `+0` | 本人 UIN |
| `+4` | Time |
| `+8` | KinIndex |
| `+0xC` | DstUIN |
| `+0x10` | Para = 0 |
| `+0x14` | Reserve = 0 |

  - 字段和 `kin.go` 的 `DecodeLocalKinOperationRequest` 一致。
  - 然后在当前频道**和**频道 0x1F 各打印一次 `【家族信息】您向玩家[%u]的邀请已经发出。`，颜色 `0x18FF00`。

### 5.13 `/c2c <uin>`（ID 0x1D）：发起交易 [证实]

- `uin ≤ 10000`：`输入的玩家QQ号不正确`，返回 0。
- 是自己（只和 `S+0x1A8` 比较）：`[温馨提示]:/yun，怎么和自己做交易！`，返回 0。
- 否则执行界面脚本 `C2CInviteNegotiate(<uin>,1)`。之后的网络交互由 Python 交易界面和 QQTDealer 负责，不在本文范围内 [未知]。

## 6. 比赛频道特权命令（需要 `ID & 0x300`）

### 6.1 `/it <uin1> [uin2 …]`（ID 0x18）：邀请队伍 [证实]

1. 不在房间里（`R+4 != 1`）：返回 0。
2. `ID & 0x300 == 0`：打印 `权限不够，无法执行此操作!`，返回 1。
3. 不在比赛频道：打印 `要在比赛频道中，才能执行此命令!`，返回 1。
4. 逐个检查 UIN：遇到 `≤ 10000` 的就打印 `输入的QQ号不正确!`，返回 0。
5. 发 **0x9E**（`net+0x34` → NetCenter `0x100160EA`，schema **0x42D**），传入 ServerID `S+0x192` 和 SectionID `S+0x194`。客户端结构：

| 偏移 | 内容 |
| --- | --- |
| `+0` | 本人 UIN |
| `+4` | Time |
| `+8` | 1 字节人数 = argCount 的低字节 |
| `+9` | 起紧排的 uint32 UIN 数组 |

- 写入指针本身放在栈上 `ebp-0x24`，数组从 `ebp-0x3F` 开始，所以**超过 6 个 UIN 会覆盖写指针**。实际上限是 6 [证实：栈偏移]。

应答处理 `FUN_10026D19`，在频道 2 打印。应答结构 [推断]：`+0` 是 2 字节结果码，`+2` 是 1 字节失败人数，`+3` 起是失败的 UIN。

| 结果码 | 文本 |
| --- | --- |
| 0 | `邀请玩家队伍成功!` |
| 4 | `邀请队伍失败. 输入了无效的玩家QQ号，或者玩家不符合比赛条件.` |
| 0xC | `您的权限不够, 无法执行此操作.` |
| 0xD | `邀请队伍失败. 房间已满.` |
| 0x2D | `邀请队伍失败, 被邀请的玩家无比赛资格.` |
| 其他 | `无法执行此操作, 可能是输入的QQ号不足或队伍的所有比赛已经结束.` |

结果码非 0 且有失败名单时，再打印一行 `邀请不成功的选手:` 加上 UIN 列表。

### 6.2 `/ct <uin>`（ID 0x19）：取消队伍比赛资格 [证实]

- 权限和频道检查同 6.1，但**不检查房间状态**。
- 发 **0x9F**（`net+0x38` → NetCenter `0x10016343`，schema **0x42C**）。12 字节 `{本人 UIN, Time, 目标 UIN}`。
- 应答处理 `FUN_10023672`，结构 `{2 字节结果码}`：
  - 0 → `取消队伍比赛资格成功!`
  - 其他 → `操作失败! 可能是输入的QQ号不正确, 无法取消队伍比赛资格.`

## 7. 管理员命令（网管/巡查员）

共同点 [证实]：

- 没有任何管理员位的普通玩家输入这些命令时，执行函数返回 0，所以只看到 `输入无效命令`，**看起来就像命令不存在**。
- 发包的时间字段用 `GetTickCount()`，不用注册表时间。
- 处罚类命令发完包，还会"公告"一行文字：
  - 未隐身（`S+0x28 == 0`）：把这行字当作**普通公共聊天**发出去，走 `FUN_10028D58(0, text, 1)`（0x6E SectionChat）。在房间里还会额外走 `FUN_100291EA`（0x6D RoomChat）。
  - 隐身中：只在本地打印，颜色用 `FUN_1001F8BD`。
- 公告里的 `%s` 是 `网管`（角色 0x40000）或 `巡查员`。

处罚请求结构，`FORBID`、`NOLOGIN` 共用（0x5A6 字节）[证实]：

| 偏移 | 内容 |
| --- | --- |
| `+0x00` | 本人 UIN |
| `+0x04` | TickCount |
| `+0x08` | 操作类型（1 禁言，2 禁止登录） |
| `+0x0C` | 时长（小时） |
| `+0x10` | 人数 = 1 |
| `+0x14` | UIN[100]，只填第一个 |
| `+0x1A4` | 2 字节理由长度 |
| `+0x1A6` | 最多 0x400 字节理由 |

`KICK`、`KICKOFF` 的结构（0x5A2 字节）[证实]：

| 偏移 | 内容 |
| --- | --- |
| `+0x00` | 本人 UIN |
| `+0x04` | TickCount |
| `+0x08` | 类型（1 踢出房间，2 踢出小区） |
| `+0x0C` | 人数 = 1 |
| `+0x10` | UIN[100] |
| `+0x1A0` | 2 字节长度 |
| `+0x1A2` | 最多 0x400 字节文本 |

### 7.1 `/FORBID <uin> [小时]`（ID 8）：禁言 [证实]

1. 选时长和理由：
   - 只有 uin（argCount==1），需要子权限 1：1 小时，理由 `请注意您的言语`。
   - 小时 == -1，需要子权限 4（只有 0x40000 有）：9999（0x270F），表示永久，理由 `请注意您的言语`。
   - 小时 == 0，需要子权限 2：解除，理由 `对您的禁言已解除`。
   - 小时 > 0，需要子权限 2：取 `min(小时, 96)`，理由 `请注意您的言语`。
   - 都不满足时：有 `0x30006` 任一位就打印 `权限不够, 无法执行此操作`，否则返回 0。
2. `FUN_100285F0` 再检查一次：角色必须是 0x40000、2、0x20000 或 0x10000（角色 4 不行）。然后发 **0x323**（`net+0xF0` → NetCenter `0x10019DA3`，schema **0x1F45**），操作类型 1。
3. 公告：
   - 时长 0：`对用户[%u]的禁言已解除`
   - 时长小于 9999：`用户[%u]因不良言行被%s禁言%d小时!`
   - 否则：`用户[%u]因不良言行被%s永久禁言!`

### 7.2 `/NOLOGIN <uin> [小时]`（ID 0xD）：禁止登录小区 [证实]

1. 角色必须是 0x40000 或 0x20000，否则返回 0。
2. 时长：
   - 只有 uin：1 小时。
   - 带小时参数：只有 0x40000 可以，取 `min(小时, 96)`，可以是 0。
3. `FUN_10028301` 再检查一次 0x40000 或 0x20000，时长必须 ≥ 0。
   - 理由：时长 > 0 时为 `您被游戏管理员踢出游戏，并限制%d小时内不能登录游戏!`。时长为 0 时理由缓冲区**没有初始化**，是原版 bug [证实]。
   - 发 **0x323**（schema 0x1F45），操作类型 2。
4. 公告：时长为 0 时是 `对用户[%u]的禁止登陆已解除`，否则是 `用户[%u]因不良言行被%s禁止登陆小区%d小时!`。

### 7.3 `/KICK <uin>`（ID 9）、`/KICKOFF <uin>`（ID 10）：踢人 [证实]

- **`/KICK`**：
  - 角色是 0x40000、0x20000 或 0x10000 时，调 `FUN_10028904(1, uin, "网管请你离开房间。")`。
  - 这个函数内部把 0x10000 归成 0，只放行 **0x40000 和 0x20000**；其余打印 `权限不够, 无法执行此操作`。
  - 发 **0x321**（`net+0xEC` → NetCenter `0x10019B4A`，schema **0x1F42**），类型 1。
- **`/KICKOFF`**：角色是 0x40000 或 0x20000 时，调 `FUN_10028904(2, uin, "网管请你离开小区。")`，发 0x321，类型 2。
- 两者都不够权限时：有 `0x30006` 任一位就打印 `权限不够, 无法执行此操作`，否则返回 0。
- 两者都不发公告。

### 7.4 `/DISMISS <房间号>`（ID 0xC）：强制解散房间 [证实]

1. 角色必须是 0x40000、0x20000 或 0x10000，否则返回 0。
2. `FUN_10028AC7` 取房间记录 `rec = 房间列表[n]`，要求 `rec+4`（房间号）等于 `n`。
3. 发 **0x325**（`net+0xF4` → NetCenter `0x10019FFC`，schema **0x1F48**），0x40C 字节：

| 偏移 | 内容 |
| --- | --- |
| `+0` | 本人 UIN |
| `+4` | TickCount |
| `+8` | 2 字节 RoomID（`rec+0x2A`） |
| `+0xA` | 2 字节长度 |
| `+0xC` | 文本 `网管解散游戏.` |

4. 公告：`[%d]号房间被%s强制解散!`。隐身时只在本地打印；未隐身时只走小区聊天。
5. 收方相关文字有 `游戏管理员强制解散了该游戏房间。`（`0x10061608`）[推断]。

### 7.5 `/INVISIBLE <n>`（ID 0x1A）：隐身开关 [证实发包；参数含义是推断]

- 角色是 0x40000、0x20000、0x10000、2 或 4 时，调 `FUN_1002D70F(n)`，发 **0xAA**（`net+0x14C` → NetCenter `0x1001B52F`，schema **0x1F55**）。12 字节 `{本人 UIN, TickCount, n}`。推断 n 用 1 表示开、0 表示关。否则返回 0。
- 应答处理 `FUN_1002D618`：
  - 设 `S+0x28 = (*(u32*)(resp+6) >> 20) & 1`；
  - 结果码 `resp+0 == 0` 时，按这一位打印 `你已开启隐身功能` 或 `你已解除隐身功能`。
  - 应答其余字段不明。

### 7.6 `/LODGE <n> <文本>`（ID 7）：投诉 [证实]

- 角色是 0x20000、0x10000、2 或 4 时才执行。注意 **0x40000 网管反而不行**：归一化代码在 0x40000 时得到 0。否则返回 0。
- 通过接口 GUID `252217e5-9e37-4e11-b925-7011fccb55af`（`0x10054400`）的 `+0x10` 调用，参数为 ServerID、SectionID、RoomID（不在房间时为 -1）和文本。**参数 n 被解析了，但根本没用**。
- 实现在 QQTModules：`0x1000ED2D` → `0x1000EE9C`。
  - 它把 `{type=2, 0x48A 字节记录}` 放进 `FUN_10014F7E` 的队列。这个队列是 `CreateFileMappingA` 建立的 64 KB 共享内存，加互斥锁，最多 31 条。
  - 外部程序不存在时弹出 `网管程序不存在，无法投诉`。
- **不发任何游戏协议包**。

### 7.7 `/SYSMSG <文本>`（ID 0xB）[证实]

解析正常，但执行函数直接返回 0，所以总是打印 `输入无效命令`。这个版本已禁用。

## 8. 跨小区消息的小格式（收方 `FUN_10026EFF`）[证实]

0x6C 的内容会原样出现在收方的 0x95 跨小区聊天通知里。收方用 `FUN_10039D67` 取第一个 `_` 之前的前缀来分类：

- **`in`**（邀请）：
  - 按键名取值：`uin`、`serverid`、`sectionid`、`roomid`、`roomflag`、`password`。
  - 在比赛频道：回 `inresult_resultid(5)`。
  - 正在接受别人的邀请：回 `(4)`。
  - `S+0xC648` 为真，或邀请人在拒绝列表里：回 `(1)`。
  - 自己正在游戏：先打印 `玩家%s[%u]邀请您一起游戏，您正在游戏不能接受。`，再回 `(2)`。
  - 否则弹窗 `玩家%s[%u]邀请您一起游戏，您是否同意？`；婚礼邀请时弹 `…邀请您观看婚礼…`。
  - 所有回复都通过 0x6C 发给邀请人，目标 PlayerID 为 `0xFFFF`。
- **`inresult`**：读 `resultid`，邀请人那边打印（`0x10027196` 起的 `dec eax` 链）：

| resultid | 文本 |
| --- | --- |
| 1 | `抱歉，%s[%u]不接受您的邀请。` |
| 2 | `%s[%u]正在游戏中，不能接受您的邀请。` |
| 3 | `%s[%u]进入房间失败。` |
| 4 | `%s[%u]正在接受别人的邀请, 暂时不能接受您的邀请.` |
| 5 | `%s[%u]在比赛频道中, 不能接受您的邀请.` |
| 其他 | `%s[%u]不能进入游戏，邀请失败。` |
