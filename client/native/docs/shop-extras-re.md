# 商城收藏柜、材料整理、赠送与修理

更新：2026-11-03。原版 v848 静态反汇编与本机服务端核对。

## 收藏柜（已接入并联调）

脚本把控件叫 `UI.shop.recycler`，界面实际叫“收藏柜”，不是删除物品。道具箱右键物品→收藏→确认，调用 `ChangeItemStatus(uin, item, 2)`；收藏柜选择物品→取回，调用同一函数状态 0。

使用已有 `0x0085 ITEM_STATUS_CHANGE`。背包绝对更新为 `0x00D9`；服务端对收藏转换先发绝对更新再发成功回复。Client.exe 的成功回复路径会同步执行 `ui_updateMyItems()` 和 `ui_updateRecycler()`，原生宿主已补齐这两个回调；仅收到物品时更新缓存不足以保证两个窗口都刷新。

本地 58000，账号 1000007 的棉绒帽 19：收藏后 `GetDisableItemInfo` 返回状态 2，道具箱移除；取回后收藏柜数量 0，物品状态 0。两个转换被服务端接受，零 warn/error。窗口截图在 `/private/tmp/qqt-mall-re/collection-live`；发送收放用宿主调用，尚未逐一验收右键和确认框的鼠标路径。

## 材料整理（已接入）

`RequestSettleStorage`：Client.exe `0x0054C9B0` → XSection `+0x300` → QQTSection `0x1002F4B9` → `0x1002BD13`。**只改本地 500 格材料仓库数组，没有网络请求。**

先遍历，将 20001～22999 号道具移到前面；遇到非道具时，从尾部找最后一个道具换入。再从第一组末尾开始，以相同方式把 30001～31999 号材料聚到第二组；合成书留在最后。因此不能用稳定分组或按 ID 排序代替。实现和专项测试在 `props.settle_storage`。不改变主背包的顺序，也不改七格装备道具栏。

材料仓库查询同时过滤数量 0 和状态 2（收藏）的记录；数量 0 是服务端绝对更新保留的删除记录，不应继续画成可用材料。原版 UI 的“整理材料”按钮已实际点击验证，无新网络请求。
