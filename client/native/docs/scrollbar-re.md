# 滚动条（SCROLLBAR / SPIN）和聊天记录滚动

脚本里的 `TVScroll`（`uiTemplate`：`type = 'SCROLLBAR'`、`style = wgtstyle_vertical`、`extendstyle = 2`）共 17 处：房间选地图、选区小区列表和区域选择、大厅/房间聊天记录、当铺/仓库、家族成员和排行、商城回收/合成/锻造、录像文件浏览。滑块是子控件 `TScrollBtn`（`BUTTON`，`moveable = 1`），部分滚动条还有 `TSpinInc`/`TSpinDec`（`SPIN`）上下箭头。实现在 `qqtclient/scrollbar.py`，以下地址都在 `gameUI.dll`。

## 控件对象

`SCROLLBAR` 由类型表 `0x100019BF` 创建：`operator new(0x298)`，构造 `0x100088AC`，虚表 `0x1003D3CC`，类型号 `+0x2C = 0x1B`。

| 偏移 | 含义 | 构造默认 |
| --- | --- | --- |
| `+0x268` | 当前位置 pos | 0 |
| `+0x26C` / `+0x270` | 范围 min / max | 0 / 10 |
| `+0x274` | pagesize（点轨道一次的步长） | 2 |
| `+0x278` | 按住轨道累计的时间（double，秒） | 0 |
| `+0x280` | 按住后开始连发的延迟 | 0.4（`0x3FD99999A0000000`） |
| `+0x288` / `+0x28C` | 最近一次悬停时的鼠标 x / y（事件 0xB） | 0 |
| `+0x290` | extendstyle | 0 |
| `+0x184 & 8` | `wgtstyle_vertical`：竖向 | |
| `+0x220..+0x22C` | clientrect（相对控件的 x、y、w、h），没写时是整个控件（`0x10027F1F`）；脚本可用 `Win_SetRect(…, value_channel_clientrect=35, …)` 改 | |

属性读取 `0x10008BEA`（虚表 `+0x14`）依次读 `extendstyle`、`range`（两个整数，交给 SetRange）、`pagesize`、`pos`（交给 SetPos）。读属性时子控件还没挂上，所以 `pos` 只做夹取，不摆滑块，也不回调。

子控件关系（添加子控件 `0x10008933`，虚表 `+0x08`）：类型号 1（`BUTTON`）的子控件记为关系 9，即滑块（多个时取最后一个）；类型号 3（`SPIN`）的子控件把滚动条记为自己的关系 6。滚动条自己的关系 6 是“通知对象”：挂在 `TEXTLIST` 下时由 `0x10023C76` 设为该列表（列表的关系 7 则是滚动条）；挂在对话框下时为空，通知不发出。关系查找见 `0x10026D8B`。

## 位置、范围与原生函数

- `Win_SetPos`（`0x1001CEAA`）和 `Win_SetScrollPos`（`0x1001CF20`）都调用 SetPos `0x10008FD3`；`Win_GetPos`、`Win_GetScrollPos` 注册的是同一个函数 `0x1001D01D`（注册处 `0x1001BC3C`）；`Win_SetRange`（`0x1001CF96`）调用 SetRange `0x10008F14(0, max(n, 0))`。四个函数都只对类型 0x1B 生效，`Win_GetPos` 对其他控件返回 0。
- SetPos `0x10008FD3`：小于 min 取 min，大于 max 取 max，然后摆放滑块 `0x10009020`。**有滑块时每次都调用脚本 `OnPosChange`（无参数），位置没变也调用**；没有滑块时直接返回，不回调（如大厅 `mapFilterDlg.scroll`，脚本只能自己 `do(…,'OnPosChange')`）。所以 `uiShop` 的 `Win_SetPos(p, Win_GetPos(p))` 就是用来刷新列表的；脚本在 `OnPosChange` 里调用 `Win_SetScrollPos`（`uiSelSect.scroll`）会嵌套回调一次，原版也是这样。
- SetRange `0x10008F14`：只在 min ≤ max 时生效；**不夹取当前位置，也不移动滑块**。所以房间选地图展开一个类型后范围变大，滑块仍停在旧处，直到下一次 SetPos。extendstyle 位 1 时把滑块长度设为“轨道长 −（max − min）”，至少 16（脚本没用到）。

## 滑块位置（`0x10009020`，伪 C 与 `idiv` 指令核对过）

记轨道为 clientrect，`span = 轨道长 − 滑块长`，`k = c_div((pos − min) × span, max − min)`（向零取整）。

| | extendstyle 位 2 置位（TVScroll 默认） | 位 2 清零（聊天记录的 `chatScroll`） |
| --- | --- | --- |
| 竖向，min < max | `y = 轨道顶 + k`（min 在上） | `y = 轨道顶 + span − k`（min 在下） |
| 竖向，min = max | `y = 滚动条自身的顶`（不加 clientrect 的 y） | `y = 轨道顶 + span`（最下） |
| 横向，min < max | `x = 轨道左 + span − k` | `x = 轨道左 + k` |
| 横向，min = max | `x = 轨道左 + span` | `x = 轨道左 + 滑块宽` |
| min > max | 不动，但仍回调 `OnPosChange` | 同左 |

竖向只改 y（`0x100284FA`），横向只改 x（`0x100284E5`），子控件随之移动。

## 点击轨道与按住连发

- 鼠标按下（事件 6，处理函数 `0x100089B3`，虚表 `+0x18`）：置按下位 `+0xE4 | 2`；若点严格落在 clientrect 内（`0x10028F26`，边界不算）且有滑块，竖向时**点在滑块上方加 pagesize，否则减 pagesize**，横向时点在滑块左边减、否则加；然后经 `0x1000900D` 走 SetPos（夹取、回调），再给关系 6 发消息 0x14（参数为新位置）。方向判断不看 extendstyle，所以从上往下排的列表（选地图、小区列表、录像文件）都把 pagesize 写成负数（`-5`、`-defSectNum`）；没写 pagesize 的 TVScroll 用默认 2，点滑块上方反而往下翻，原样保留。聊天记录的滚动条是自下而上的，pagesize 为正（6、8）。
- 每帧更新 `0x10008B13`（虚表 `+0x58`）：没按住时清零计时；按住时累加，超过 0.4 秒后**每帧**按 `+0x288/+0x28C` 记下的鼠标位置再翻一次：竖向鼠标在滑块上方加 pagesize、在滑块下方（超过滑块底）减 pagesize、在滑块范围内不动；横向对应减/加。计时不复位，所以不会变慢，然后照样给关系 6 发 0x14。pagesize 对应的像素比滑块长时，滑块会在鼠标两侧来回跳，原版如此。
- 松开（事件 7）清按下位；鼠标离开（基类 `0x1002ADEB` 事件 0xD）清掉位 1、2，所以移到滑块或滚动条外就停止连发。宿主按“按下的控件仍是它，并且鼠标仍悬停在它上面”判断按住。

## 拖动滑块

- 按下（分发 `0x100304C8` 的 `WM_LBUTTONDOWN`）：先设焦点；若命中的控件可移动（`+0x185 & 0x18`，`moveable` 经 `0x10028C04` 置 `0x800|0x1000` 两轴）且点在拖动区内（`0x10028EC3`，默认整个控件），记为“移动中的控件”（管理器 `+0x2B8`），偏移为控件左上角减按下点（`+0x70C/+0x710`），再照常发事件 6。
- 移动（`WM_MOUSEMOVE`）：有移动中的控件时只给它发 0x19（目标点 = 鼠标 + 偏移），不做悬停处理。基类 0x19：先让父控件夹取（滚动条为 `0x10008E4E`：x、y 分别夹到 clientrect 内，先夹下界再夹上界），按 `0x800`/`0x1000` 决定改哪一轴，移动后给父控件发 0x1A。
- 滚动条处理 0x1A（`0x100091BC`）：由滑块位置反算 `pos = min + c_div(along × (max − min), span)`（竖向且位 2 置位、横向且位 2 清零时 `along = 滑块到轨道起点的距离`，另两种取 `span − along`；`span < 1` 时为 0），走 SetPos（滑块吸附到该位置、回调 `OnPosChange`），再给关系 6 发 0x14。所以拖动时滑块是一格一格跳的。
- 松开（`WM_LBUTTONUP`）：只给移动中的控件发事件 7 并清掉记录，不再做命中检测，不触发别的点击。

## SPIN 箭头

`SPIN` 构造 `0x10004769`（基于 `BUTTON` 构造 `0x10003F1D`，类型号 3，虚表 `0x1003C6B8`，与 `BUTTON` 共用事件处理 `0x10004321` 和绘制）。点击（虚表 `+0xD8`，`0x10004879`）先回调脚本 `OnClick`（`0x1002E87A`），再给关系 6（滚动条）发 0x13，参数为自己的 style。滚动条收到 0x13：style 含 `wgtstyle_primary`（16，`TSpinInc`）加 1，否则（`TSpinDec`）减 1，只有新值仍在 [min, max] 内才走 SetPos；然后给关系 6 发 0x14。按住时 `0x10004811` 同样在 0.4 秒后每帧重复“`OnClick` + 0x13”。

## 聊天记录（TEXTLIST）的滚动

`TEXTLIST` 构造 `0x10023B63`：`scrollspace`（`+0x2A8`）默认 1，`maxline` 200，`linemargin` 4。滚动量是像素偏移 `+0x2A0`，0 表示最新一行贴在底部。

- 排版 `0x10025472`/`0x10023856`：每条记录按 clientrect 宽折行，n 行高 `(n − 1) × (textsize + rowspace) + textsize`；条目从上往下排，每条上方空 rowspace，最后再加一个 rowspace，得到总高 `+0x2A4`。
- 绘制 `0x10025083`：条目画在 `client 顶 + client 高 − 总高 + 偏移 + 条目 y`。所以记录不满一屏时贴在底部，偏移越大越往回看；只画与 client 区相交的条目。
- 内容变化后的重排 `0x1002559C`（每帧更新 `0x10024051` 在脏标志 `+0xE5 & 0x20` 置位时调用；`Win_Update` `0x1001D0B4` 就是置这个标志）：滚动条只在总高大于 client 高时启用（`0x10028B84`），范围为 `[0, ceil((总高 − client 高) / scrollspace)]`，再按原偏移重新夹取。新消息到来时偏移不变，所以往回看时画面会随新消息上移。
- 设偏移 `0x100253C8`：夹到 `[0, 总高 − client 高]`，再把滚动条设为 `ceil(偏移 / scrollspace)`（SetPos，滑块随之移动）。滚动条发来的 0x14 把偏移设为 `scrollspace × pos`（`0x10023F0A`）。
- 滚轮：`WM_MOUSEWHEEL`（分发 `0x100304C8`）发给焦点（`+0x2AC`），没有时给捕获（`+0x2B4`），再没有给悬停的控件（`+0x2B0`），消息 0x11。只有 `TEXTLIST`（`0x10023F0A`）和 `LISTBOX`（`0x10009A99`，脚本没用到）处理它，其余控件（包括滚动条和滑块）交给父控件（基类默认分支）。`TEXTLIST` 把滚轮增量（一格 120，向前为正）直接加到像素偏移上（`0x100253B5`）。**滚轮跟随焦点而不是鼠标位置**：大厅点聊天记录时脚本会把焦点交回输入框，所以只有点过聊天栏的滚动条（焦点落在滚动条或滑块上）之后滚轮才能翻聊天记录；房间、商城同理。
- 命中检测用控件自己的窗口矩形（`0x10028EE8`），不是 clientrect。大厅聊天栏放大后脚本只改了滚动条的 clientrect（高 186/281），窗口矩形仍是 90 高，所以轨道只有上面 90 像素能点；滑块是子控件，在哪都能拖。原版如此，照样实现。

## 宿主实现与差异

- `widgets.py` 在构造 `SCROLLBAR`/`SPIN`/`TEXTLIST` 时调用 `scrollbar.init`/`init_list`；`natives.py` 的五个原生函数按上文实现；`runtime.py` 处理轨道按下、滑块拖动、`SPIN` 点击、按住连发和滚轮；`render.py` 的 `list_rows` 按原版公式排 `TEXTLIST` 并更新它的滚动条。
- 推断/近似：原版只在脏标志置位时重排 `TEXTLIST`，宿主在总高、client 区或滚动条尺寸变化时重排（滚动条上没有脚本 `OnPosChange`，结果相同）。按住连发按宿主帧率（60 帧）每帧一次，原版帧率没有查。滚轮方向取 SDL 的 `y`（macOS 的“自然滚动”已由系统换算），一格算 120。
- 未改：`TEXTLIST` 折行宽度仍是宿主原来的 client 宽 − 16，没有 clientrect 时仍退回 captionrect（原版用整个控件）；这两点属于聊天排版，留给 `TEXTLIST` 的专项核对。`TEXTLIST` 的键盘翻页（`0x10023FF9`：PageUp/PageDown 按页、上下键按 textsize）、`LISTBOX` 的滚动都没做（焦点几乎不会落在聊天记录上，脚本也没用 `LISTBOX`）。

## 验证

- `tests/test_scrollbar.py`（12 项）：构造默认值、SetPos 夹取与回调、无滑块不回调、SetRange 不动位置、两种方向的滑块位置、轨道翻页与 0.4 秒后连发、拖动吸附且不触发点击、SPIN 步进与越界、按住 SPIN 连发、聊天记录贴底与禁用、轨道/滚轮翻聊天记录、滚轮跟随焦点、新消息保持偏移。
- 实测（测试服 58000，账号 1000011）：房间选地图点轨道翻到底、展开“野外”后拖动滑块到第 13 格，选中第二屏的“QQ森林”（map 120）并确定，房间预览换成该图；大厅聊天写入 30 行后点轨道往回翻 8 格、滚轮往下 1 格（偏移 144→24）、把滑块拖到顶看到第 0 行，再来 3 条新消息时画面上移、范围变大；录像浏览切到客户端根目录后点轨道翻 5 格；选区、区域选择、商城界面无脚本错误。
