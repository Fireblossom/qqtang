# NPC路径消费与漫游缓存

2026-11-04，v848 `0x005B1EA6` 随路、`0x005DEF29` AIType2控制器、`0x005B0A88` 时间门控实际执行。探针为 `tools/probe_npc_follow.py`，67条记录在 `tests/fixtures/npc_follow_v848.jsonl`。本轮生产接入的是漫游方向缓存；完整路径消费和连续物理仍未移植，不能把原生探针通过记成生产移动全量一致。

## 随路的返回值不等于路径是否为空

原版向量 `N+0x760/764` 按目标→起点存放6字节节点；尾项是当前待消费节点。`0x005B0598` 在已有向量后追加新逃生，因此新路线先被访问，旧路线在底部保留。

`0x005B1EA6` 实测：

1. 入口不足两个节点时清空，失配计数 `N+0x7AC` 归零，返回1。
2. 用截断后的像素坐标除40得到当前格。尾项不在当前格时，逐个弹尾并递增失配计数；计数严格大于10时清空路线、归零、吸附到当前格中心。计数为uint32，FFFFFFFF递增会回绕0。
3. 对齐当前格后，若还剩至少两个节点，分别对“当前坐标−当前格中心”截断取绝对值；两轴都小于10时弹掉当前节点、计数归零、**立即返回1**。并非在此直接沿下一节点方向继续。
4. 否则有节点就做前方碰撞预判。可通过，或者角色处于standing（`N+0x3B8==1`），返回0并保留路线。walking受阻则清空、吸附当前格中心、归零并返回1。
5. 失配把向量弹空但计数未超10时，返回1，计数暂时保留；下一次入口空向量才归零。

因此函数返回1时可能仍有多个节点；不能一律解释成“路线耗尽”。控制路线 `(6,5)→(6,6)→(7,6)` 在首格中心弹起点后返回1；在下一格中心弹中间项后同样返回1。若本次失配后只剩终点，仍可能进入投影分支，哪怕该节点方向为9；本探针保留此异常输入的实际观察，不将它推广成合法移动方向。

## 投影方向与碰撞朝向不同

`0x005B1E89` 读取 `0x007F2BB4`：`[0,1,2,2,2,2,2,2,2,8,13.333]`。它是前方检查距离表，**不是**NPC运动速度表 `0x007F4988`。距离乘场景本帧dt和0.04，沿尾节点的方向投影，最后截断像素坐标。

`0x005B7999(x,y,facing,0,0,1)` 中的facing另取角色 `N+0x3B4`，可能与节点方向不同。探针故意让二者不同，四方向×五档速度均核实。17ms下，从x230.5向右：一档预判x231、九档x235、十档x239。

位置setter和碰撞谓词是控制依赖；路径向量、阈值、计数、投影和站立分支执行原函数。属性 `0x005AA06B` 的 `+0x2B0!=FF` 路径实际固定返回2，不能把该字节当成任意速度覆盖。本探针明确控制该属性getter返回不同档位，仍执行角色VM包装 `0x0087E6CA`。另一探针 `probe_box_ai.py` 只需合法的固定二档返回以维持x87栈平衡，不靠它验证其他档位。

## AIType2：危险优先、500ms门控、格子缓存

`0x005DEF29` 顺序为：

1. 危险判断不为0，直接转逃生 `0x005B214D`，跳过时间门控。
2. 安全时 `0x005B0A88` 未放行，返回当前朝向，既不消费路径也不取随机数。
3. 门控放行后调用随路；返回0则返回尾节点方向。
4. 随路返回1后，若当前格等于缓存且未受阻（`N+0x7C8==0`），直接返回缓存方向 `N+0x7D8`；否则更新格子并调用漫游选择 `0x005B0ACA`。

缓存原始short顺序为 **`+0x7CC=row, +0x7CE=col`**。在相同格里，即使方向掩码变化、甚至变成0，也复用缓存方向，不重新抽随机数。受阻才使缓存失效。原版返回寄存器高24位可能残留指针，控制器结果只取低8位。

`0x005B0A88` 比较 `abs(int32(sceneTime-lastTime)) > 499`；满足时通过角色虚表+68写回当前时间。499ms不放行，500ms放行；时间逆向相差500ms也放行。这个门控与移动命令的帧计数是不同层次，尚未把整个调度移植完成。

生产的 `npcWanderCache` 已接到箱子NPC原有中心点移动器：相同格且未受阻时保留方向，不消耗RNG；目标格被挡时记录受阻，真正移动后清除此标志。8条原生控制器缓存记录逐项核对方向、缓存格、缓存方向及随机调用数。既有中心移动器无可走方向时仍停步，这一层尚未改造成原版的连续运动/碰撞反馈。

67条记录包含：47条随路与投影、11条控制器上下文、9条真实时间门控。全部可重新运行生成；只有上述8条缓存记录直接作为本轮Go实现的对照，其他记录是下一阶段完整路径栈/连续物理的证据。
