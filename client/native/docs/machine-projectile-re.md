# 机器发射物165/166：两段轨迹与帧周期

2026-11-03。来源：最终版Client.exe普通汇编、Unicorn执行、原版DIMG及1302双客户端实测。宿主实现 `battle/machine_projectile.py`，不改投泡/伤害/结算协议。

## 对象及路径

机器初始化 `0x005EF47A` 创建两个 `0x0060881F` 对象（虚表 `0x007A4224`），初始化参数分别165/166。`0x00608878` 将编号组成 `0x07000001 | number<<8`，两张图片均为4帧：165画布60×60，166为60×100。原包这两张及167/168的stand/trigger文件逐字节相同。

`0x005EF91F` 第一次绘制设置路径。令机器元素锚点为 `(row,col)`：

```text
muzzle = ((col-1)*40 + (首侧?80:30), (row-2)*40+20)
apex   = (280, (row-2)*40-60)
第一段165：muzzle → apex
第二段166：apex → (280,0)
```

这里写的是通常的(x,y)；原函数 `0x006088EC` 的两短整数点实际上先存y、后存x。`0x005EFB2D` 在机器启动时将两个active置1并恢复各自起点，**不重置图片动画相位**。

父更新 `0x005EF7DE` 在启动后至少700ms时，对第一段调用 `Update(1)`；第一段已停时，对第二段调用 `Update(2)`，可在同一次父更新内换段。绘制也跟随active切换。

## 原版每次更新的运动

`0x006089C5` 的参数不是实际经过毫秒：第一段每次沿x方向1像素，y按斜率跟随；竖直第二段每次沿y方向2像素。斜率和每次位置存储均为float32。若目标在当前值另一侧则反向推进，包括顶部机器的apex可能在y<0、第二段反而向y=0移动。

每次移动后，截断的**剩余距离平方小于4**就停止；不是“坐标恰等于终点”才停。停止的第一段不再绘制，第二段同帧已走一步。宿主保留逐次推进，按对局宿主每帧更新一次，不把它改成固定像素/秒；不同帧率可造成纯画面的到达时刻不同。

Unicorn运行真实构造、路径设置及移动函数，CRT `_ftol` 用弹出x87值并向零截断的桥接替代；原始像素解码/绘图不参与位置运算。原生结果及移植测试一致：

| row,col,侧 | 第一段停在第几次更新 | 两段全部结束 |
| --- | ---: | ---: |
| 6,3,首侧 | 119 | 168 |
| 6,10,另一侧 | 109 | 158 |
| 3,3,首侧（apex在屏幕上方） | 119 | 128 |
| 9,10,另一侧 | 109 | 218 |

例如第一行第119次：第一段位置 `(279,100.6663818359375)`，第二段已在 `(280,98)`；第一段第1次为 `(161,179.3333282470703)`。测试使用这些独立原生结果，包含浮点存储和同帧切换。

## 图片推进

`0x0060897C` 每次将 `amount*10` 交给图片更新，所以两段每次分别推进图片时间10/20ms。原版图片数据构造 `0x00487360` 的帧周期为 **300ms**、循环开启；不是宿主通用的100ms。`0x0042A680` 消耗此周期。

已实际执行上述图片数据构造及动画推进函数，只将原始DIMG帧数查询替换为已读取的4：10ms步进第29次仍为帧0，第30次为帧1，第90次为帧3，第120次回帧0；20ms步进第15次为帧1，第60次回帧0。宿主据此使用300ms周期，并保留多次发射之间的相位。

绘制沿用机器本体的原版SetPos到宿主坐标换算，额外图片锚点为(0,0)，保留DIMG自身裁剪偏移。发射物在机器本体后、本机就绪箭头前绘制，设备毁掉后移除对应画面状态。
