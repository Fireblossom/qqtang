# 普通Boss保留行走命令与默认浮点物理

2026-11-04。AIType3的未变身Boss已撤下“选方向后只走到邻格中心”的移动近似，改为在两次决策间持续保留行走命令，并使用已移植的默认float32碰撞/滑角及完整Corner/End预测。

## 原版路径与规则参数

移动命令 `0x006112AF` 计数超过5时才调用AI返回方向；其余帧没有新指令，旧的角色行走状态继续有效。世界更新 `0x005F3D0A` 每帧依据Actor+3B8/+3B4调用 `0x005CF8D9`，后者执行 `0x005CFC10` 并通过真实 `0x005AD322` 写回位置；随后 `0x005CF9B8` 从新位置进行25ms步长预测。遇到相邻格中心本身不会停步。

探针实际执行 `0x005F47A9(world,1)` 创建规则1对象，虚表 `0x007A37F0`，+2C指向 `0x005F49B5`，返回角滑容差6。另行实际构造规则2/8/12分别得到2/6/6；规则8与规则1使用同一个6值getter。此前3648条通用内核矩阵使用受控容差10测试边界，不代表规则8的真实getter返回10；宿主规则默认值原本就是6，本轮没有把默认容差改成10。

## 原生对照

```sh
.venv/bin/python tools/probe_boss_motion.py /path/to/client-patched
```

`boss_motion_v848.jsonl` 共349条：1条真实规则构造/getter见证，加348组角色32、四方向、1/3/8档、16帧保持序列，共5568个运动/预测快照。覆盖容差6附近偏移、前方/侧方障碍、持续穿过格心和停止命令。

真实速度表getter、`0x005CF8D9`、位置setter、默认位移内核及预测函数执行。网格碰撞谓词、地形出口、地图尺寸、默认穿越能力、空图片/场景与NPC登记查询是受控依赖；必要的基础速度属性也是显式输入，校正标记触发的真实VM getter未被替换，没有懒映射未知内存。此探针没有执行Boss完整构造或AI寻路决策。

例如起点(259.75,260)、向右3档、每帧20ms：前3帧为x262.21160888671875、264.6732177734375、267.13482666015625，预测终点(580,260)。旧宿主会先钳制到x260并清空邻格路径；新宿主持续行走。

Go通过注册Boss身份的正式引擎/共用移动函数，逐帧比较位置float32位模式、是否位移、Corner及End。另一个回归经真实 `bossTick→bossGeneral.tick` 验证连续6帧越过格心，保留行走并发送完整预测。旧的私有邻格目标经过后会退休，供特殊能力的兼容路径使用时不会再倒走回该目标。

## 接入与验证边界

共用函数更名为 `moveDefaultNPC`。普通Boss在决策成功时更新保留方向/行走状态，停止返回9时停止；无新决策时继续推进。初次接管控制器从现有角色移动状态初始化，不把已有行走强行当成站立。

变身Boss、踢炸弹/其他特殊控制器和探险仲裁移动仍有独立兼容路径，本轮没有把它们冒称为全量精确物理。通用Boss的寻路消费、放泡规划/命令顺序及20ms到源Win32渲染帧的调度仍需继续核对；本轮349条只证明默认保持位移/预测及宿主接入，不证明整个AI等价。

相关侧车、引擎和协议测试通过；放泡逃生回归现运行到首颗泡实际爆炸后，确认Boss存活且HP不变，不再在放泡当帧要求未发出的移动。共用探针环境抽取后重新生成旧3648条基准，与原fixture完全一致。Mac正式构建与Windows/386交叉构建通过。

累计NPC/共用模型基准7526条（7177+349）；序列内5568帧不重复计数。
